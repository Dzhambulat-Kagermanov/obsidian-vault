**Цель:** Построение приложений, которые легко тестировать и масштабировать годами. **Что записать:**

- **Clean Architecture (Hexagonal) в NestJS:** Разделение на слои: Domain (Entities, Interfaces), Application (Use Cases/Services), Infrastructure (Prisma, External APIs), Presentation (Controllers). Запрет на импорт из Infrastructure в Domain.
- **CQRS (Command Query Responsibility Segregation):** Использование `@nestjs/cqrs`. Разделение операций чтения (Queries) и записи (Commands). Когда это нужно (сложные домены), а когда это over-engineering.
- **Event-Driven внутри приложения:** Использование `EventEmitterModule` или `@nestjs/cqrs` Event Bus для слабой связности модулей (например, после создания пользователя генерируется событие `UserCreatedEvent`, на которое подписан модуль отправки email).
