**Цель:** Создание надежных точек входа (API endpoints), которые отвергают некорректные данные до попадания в бизнес-логику. **Что записать:**

- **Контроллеры:** `@Controller`, `@Get`, `@Post`, `@Param`, `@Query`, `@Body`. Извлечение кастомных декораторов (например, `@User()` для получения данных из JWT).
- **DTO (Data Transfer Object):** Классы с декораторами. Почему нельзя использовать Entity/Model классы как DTO (риск утечки паролей или внутренних полей).
- **Валидация:** Глобальный `ValidationPipe` с опциями `whitelist: true` (отсечение лишних полей) и `forbidNonWhitelisted: true`. Использование `class-validator` (`@IsString`, `@IsEmail`, `@IsOptional`) и `class-transformer` (`@Type(() => Date)`).
- **Сериализация:** Декоратор `@Exclude()` и `@Expose()` из `class-transformer` для контроля того, какие поля уходят в ответе (альтернатива ручному маппингу).

**Цель:** Грамотное описание API и извлечение данных из запроса. **Что записать:**

- **Базовые декораторы:** `@Controller('users')`, `@Get(':id')`, `@Post()`, `@Put()`, `@Delete()`, `@Patch()`.
- **Извлечение данных:** `@Param('id')`, `@Query('filter')`, `@Body()`, `@Headers()`, `@Ip()`.
- **Создание кастомных декораторов:** Пошаговый гайд создания `@User()` или `@TenantId()` декоратора с использованием `createParamDecorator` и `ExecutionContext` (чтобы не писать `req.user` в каждом контроллере).
- **Версионирование API:** Настройка `@Controller({ version: '1' })` и глобальная настройка в `main.ts`.
