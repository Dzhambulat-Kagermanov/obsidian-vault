**Цель:** Построение предсказуемого потока данных без избыточной реактивности и "prop drilling". **Что записать:**

- **Иерархия состояний (Правило близости):** Состояние должно жить как можно ближе к месту его использования.
- **Типы состояний и инструменты:**
    - _Локальное UI:_ `useState`, `useReducer`.
    - _Серверное состояние:_ TanStack Query (React Query), SWR или Next.js `fetch` (почему не стоит класть данные API в глобальный стейт).
    - _Глобальное клиентское состояние:_ Zustand, Jotai или Valtio (почему Redux Toolkit часто избыточен для новых проектов).
    - _URL как состояние:_ Использование `useSearchParams` для фильтров и пагинации (лучшая практика для шеринга ссылок).
- **Ловушки Context API:** Почему Context — это механизм внедрения зависимостей (DI), а не менеджер состояния. Проблема лишних ререндеров при изменении значения контекста и способы её решения (разделение контекстов, `useContextSelector`).
