**Цель:** Правильная, безопасная и производительная работа с базой данных в serverless-среде Next.js. **Что записать:**

- **Проблема Serverless и пулов соединений:** Почему прямое подключение к Postgres из Next.js (особенно на Vercel) приводит к ошибке "too many connections". Решение: использование **Supabase Connection Pooling** (Transaction mode) или сторонних пулеров (PgBouncer, Neon).
- **Паттерн Singleton для клиента БД:** Как правильно инициализировать клиент Supabase или Drizzle в глобальной области видимости (`globalThis`), чтобы не пересоздавать его при каждом hot-reload или serverless-холодном старте.
- **Разделение клиентов:**
    - _Server Client:_ Использует `service_role` ключ (или ключ с обходом RLS) для админских задач.
    - _Client (Browser) Client:_ Использует `anon` ключ и работает строго через Row Level Security (RLS).
- **Drizzle ORM / Prisma:** Почему Drizzle сейчас предпочтительнее в Next.js (меньший размер бандла, лучшая поддержка Server Components, нативная работа с PostgreSQL/Supabase). Пример типизированного запроса.
