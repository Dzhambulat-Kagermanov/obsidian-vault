**Цель:** Организация кодовой базы, которая масштабируется без превращения в "лапшу". **Что записать:**

- **Структура папок:** Feature-based (по функциональным модулям: `auth/`, `dashboard/`, `products/`) vs Layer-based (по типу файлов: `components/`, `lib/`, `app/`). Рекомендация: гибридный подход с выносом переиспользуемых частей в `src/components` и `src/lib`.
- **Передача данных:** Почему в RSC-мире не нужно использовать Context API для передачи данных с сервера. Данные запрашиваются на сервере и передаются вниз как обычные пропсы. Context оставляем только для истинно глобального клиентского стейта (тема, локаль).
- **Обработка ошибок:** Глобальный `error.tsx` vs локальные try/catch в Server Actions с возвратом структурированных объектов `{ error: "message", success: false }`.
