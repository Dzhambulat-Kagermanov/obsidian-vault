
Провайдер `camptocamp/freeipa` для Terraform предназначен для **автоматизации управления ресурсами FreeIPA** с использованием инфраструктуры как кода (IaC). Он позволяет администраторам описывать состояние объектов FreeIPA в конфигурационных файлах Terraform и автоматически применять их, вместо ручного создания через веб-интерфейс (WebUI) или командную строку (CLI)

**Основные функции и возможности провайдера:**

- **Автоматизация DNS:** Управление DNS-записями (A, AAAA, CNAME, SRV и др.) внутри FreeIPA.
- **Управление пользователями и группами:** Автоматическое создание, обновление и удаление пользователей и групп.
- **Управление хостами:** Регистрация и настройка клиентских узлов.
- **Интеграция с CI/CD:** Позволяет включать настройки FreeIPA в пайплайны развертывания инфраструктуры.

### Настройка подключения:

```hcl
terraform {
  required_providers {
    freeipa = {
      source  = "camptocamp/freeipa"
      version = "~> 0.8.0" # последняя стабильная ветка
    }
  }
}

provider "freeipa" {
  host         = "10.10.10.10"
  username     = "admin"
  password     = var.ipa_password
  ca_cert_path = "/path/to/ipa-ca.crt"
  # insecure = false # по умолчанию false
  # otp        = null # опционально: TOTP токен
}
```

| Параметр   | Тип      | Обязательный | Описание                                                                  |
| ---------- | -------- | ------------ | ------------------------------------------------------------------------- |
| `host`     | `string` | ✅            | FQDN FreeIPA сервера (например, `ipa.corp.example`)                       |
| `username` | `string` | ✅            | Пользователь с правами администратора                                     |
| `password` | `string` | ✅            | Пароль (автоматически помечается как `sensitive`)                         |
| `cacert`   | `string` | ❌            | Путь к локальному PEM-файлу CA (если сертификат не в системном хранилище) |
| `timeout`  | `string` | ❌            | Таймаут запросов (например, `"30s"`, `"2m"`)                              |

**Соответствие параметров и переменных окружения:**

- `host`: `FREEIPA_HOST`
- `username`: `FREEIPA_USERNAME`
- `password`: `FREEIPA_PASSWORD`
- `insecure`: `FREEIPA_INSECURE`

> **Важно!** Провайдер использует **HTTPS + Kerberos-аутентификацию через XML-RPC**. Если `cacert` не указан, он полагается на системные CA.

### freeipa_host:

Ресурс `freeipa_host` — это инструмент для регистрации и управления серверами или рабочими станциями в домене FreeIPA. Его основная задача — не развернуть саму виртуальную машину, а **сообщить серверу FreeIPA о существовании нового хоста, выдать для него идентификационные данные (принципала Kerberos) и настроить правила делегирования**

Представьте, что вы создали новую виртуальную машину с помощью другого Terraform-ресурса (например, в OpenStack, AWS или VMware). Чтобы эта машина стала частью вашего домена, на нее нужно установить клиентские пакеты FreeIPA и выполнить команду `ipa-client-install`. Для успешного выполнения этой команды хост уже должен быть **заранее зарегистрирован** в каталоге FreeIPA.

Именно эту регистрацию и выполняет `freeipa_host`, предоставляя все необходимые данные для автоматического ввода машины в домен

```hcl
resource "freeipa_host" "example" {
  fqdn        = "my-server.example.com" # Полное доменное имя хоста
  description = "Мой тестовый сервер"
  force       = true # Удалить хост, даже если он не отвечает
  random      = true # Сгенерировать случайный пароль для хоста
  userpassword = "secure_password" # Установить пароль для хоста
}
```

**Параметры:**
- **`fqdn`** (обязательный): Полное доменное имя хоста (например, `web-server-01.example.com`). Это уникальный идентификатор хоста в IPA.
- **`description`**: Текстовое описание хоста для удобства администрирования.
- **`userpassword`** и **`random`**: Эти параметры определяют пароль, который будет использоваться при вводе хоста в домен. Вы можете установить его вручную через `userpassword` или, что рекомендуется для безопасности, установить `random = true`, чтобы пароль был сгенерирован автоматически [](https://pkg.go.dev/github.com/camptocamp/terraform-provider-freeipa).
- **`force`**: Если установлено `true`, позволяет принудительно удалить запись о хосте из FreeIPA, даже если сам хост в данный момент недоступен. Удобно для очистки "мертвых" записей.

**Связь с `ipa_client` и другими инструментами:**

Ресурс `freeipa_host` сам по себе не устанавливает клиентское ПО. Он готовит "учетную запись" для хоста в каталоге. Следующий шаг обычно выполняет система управления конфигурациями (например, Ansible):

1. **Terraform**: Создает ресурс `freeipa_host` и генерирует для него одноразовый пароль (благодаря параметру `random = true`).
2. **Terraform**: Передает этот сгенерированный пароль в Ansible (например, через `output`).
3. **Ansible**: Использует модуль `ipaclient`, передавая ему FQDN хоста и полученный пароль для автоматической установки и настройки клиента.

Таким образом, `freeipa_host` является ключевым звеном в цепочке автоматизации, обеспечивая безопасную и контролируемую регистрацию новых машин в вашем домене.

### freeipa_user:

**Создание и управление учетной записью** пользователя. Это сам объект пользователя в каталоге FreeIPA. Этот ресурс отвечает за полный жизненный цикл учетной записи пользователя.

#### Обязательные поля:

| Поле             | Тип      | Описание                                                                                                                                       |
| ---------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **`name`**       | `String` | **UID пользователя** — уникальный логин для входа в домен. Именно это значение используется при аутентификации (например, `jdoe@EXAMPLE.COM`). |
| **`first_name`** | `String` | Имя пользователя.                                                                                                                              |
| **`last_name`**  | `String` | Фамилия пользователя.                                                                                                                          |

**Минимальная конфигурация:**

```hcl
resource "freeipa_user" "john_doe" {
  name       = "jdoe"
  first_name = "John"
  last_name  = "Doe"
}
```

#### Опциональные поля — пароль и параметры безопасности:

| Поле                           | Тип              | Описание                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------ | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **`userpassword`**             | `String`         | Пароль пользователя. **Поле помечено как `Sensitive`** — Terraform не будет отображать его в логах. Не рекомендуется хранить пароль в коде в открытом виде.                                                                                                                                                                                                                                                                                                                                                                                |
| **`random_password`**          | `Boolean`        | Если установлено `true`, FreeIPA сгенерирует случайный пароль для пользователя. Этот пароль **сразу же помечается как истёкший** (expired). Сгенерированный пароль возвращается в Terraform как чувствительное (`sensitive`) значение (например, `ipauser.user.randompassword`), чтобы администратор мог его увидеть и передать пользователю. При первой же попытке входа система потребует сменить пароль. Это сделано из соображений безопасности, чтобы сгенерированный пароль, который знал администратор, не стал постоянным секретом |
| **`account_disabled`**         | `Boolean`        | Если `true`, учётная запись заблокирована (аналог `nsaccountlock` в LDAP). Пользователь не сможет аутентифицироваться.                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **`krb_password_expiration`**  | `String`         | Дата истечения срока действия пароля в формате **RFC3339** (например, `2025-12-31T23:59:59Z`). После этой даты пользователь будет вынужден сменить пароль.                                                                                                                                                                                                                                                                                                                                                                                 |
| **`krb_principal_expiration`** | `String`         | Дата истечения срока действия Kerberos-принципала в формате **RFC3339**. После этой даты учётная запись станет неактивной для Kerberos-аутентификации.                                                                                                                                                                                                                                                                                                                                                                                     |
| **`krb_principal_name`**       | `List of String` | Список альтернативных имён Kerberos-принципала (алиасов). Например, `["admin/jdoe@EXAMPLE.COM"]` для сервисных аккаунтов.                                                                                                                                                                                                                                                                                                                                                                                                                  |

**Конфигурация с настройками безопасности:**

```hcl
resource "freeipa_user" "secure_user" {
  name       = "tempworker"
  first_name = "Temporary"
  last_name  = "Worker"

  # Генерация случайного пароля вместо хардкода
  random_password = true

  # Учётная запись активна
  account_disabled = false

  # Пароль истечёт через 90 дней (примерная дата)
  krb_password_expiration = "2025-07-15T00:00:00Z"

  # Принципал действителен до конца года
  krb_principal_expiration = "2025-12-31T23:59:59Z"

  # Альтернативный принципал для сервисных задач
  krb_principal_name = ["service/tempworker@EXAMPLE.COM"]
}
```

#### Опциональные поля — параметры системной учётной записи:

| Поле                 | Тип              | Описание                                                                                                                                                                                           |
| -------------------- | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`uid_number`**     | `Number`         | Числовой идентификатор пользователя (UID). **Если не указан, FreeIPA назначит его автоматически.** Ручное указание требуется редко, обычно для миграции или синхронизации с legacy-системами.      |
| **`gid_number`**     | `Number`         | Числовой идентификатор **первичной группы** пользователя (GID). По умолчанию используется GID стандартной группы `ipausers`.                                                                       |
| **`home_directory`** | `String`         | Путь к домашней директории (например, `/home/jdoe`). Если не указан, формируется автоматически по шаблону `/home/<uid>`.                                                                           |
| **`login_shell`**    | `String`         | Путь к оболочке входа (например, `/bin/bash`, `/bin/zsh`). По умолчанию определяется глобальными настройками FreeIPA или клиентской машины.                                                        |
| **`ssh_public_key`** | `List of String` | Список публичных SSH-ключей пользователя. Ключи записываются в формате OpenSSH (например, `"ssh-rsa AAAAB3NzaC... user@host"`). Это централизованно управляет доступом по SSH на все хосты домена. |

**Конфигурация с системными параметрами:**

```hcl
resource "freeipa_user" "developer" {
  name       = "adev"
  first_name = "Alice"
  last_name  = "Developer"

  uid_number     = 10001               # Явное указание UID (опционально)
  home_directory = "/home/adev"
  login_shell    = "/bin/zsh"

  ssh_public_key = [
    "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI... alice@workstation",
    "ssh-rsa AAAAB3NzaC1yc2EAAA... alice@laptop"
  ]
}
```

#### Опциональные поля — персональная информация:

|Поле|Тип|Описание|
|---|---|---|
|**`full_name`**|`String`|Полное имя (`cn` в терминах LDAP). Если не указано, FreeIPA автоматически формирует его из `first_name` и `last_name`.|
|**`display_name`**|`String`|Отображаемое имя в веб-интерфейсе FreeIPA и других системах. Может отличаться от `full_name` (например, включать предпочитаемое обращение).|
|**`initials`**|`String`|Инициалы пользователя.|
|**`gecos`**|`String`|Поле GECOS — устаревшее, но до сих пор используемое в UNIX-системах для хранения информации о пользователе (обычно полное имя, телефон и т.д.).|
|**`job_title`**|`String`|Должность пользователя в организации.|
|**`employee_number`**|`String`|Табельный номер сотрудника.|
|**`employee_type`**|`String`|Тип сотрудника (например, `intern`, `contractor`, `full-time`).|
|**`manager`**|`String`|Непосредственный руководитель пользователя. Обычно указывается UID менеджера.|
|**`organisation_unit`**|`String`|Подразделение или отдел организации.|
|**`preferred_language`**|`String`|Предпочитаемый язык пользователя (например, `en_US`, `ru_RU`). Влияет на локализацию интерфейсов.|
|**`userclass`**|`List of String`|Категория пользователя. Семантика этого атрибута определяется локально в организации (например, `employee`, `admin`, `service-account`).|

**Расширенная конфигурация с персональными данными:**

```hcl
resource "freeipa_user" "jane_smith" {
  name              = "jsmith"
  first_name        = "Jane"
  last_name         = "Smith"
  full_name         = "Jane Smith"
  display_name      = "Jane S."
  initials          = "JS"
  job_title         = "Senior DevOps Engineer"
  employee_number   = "EMP-12345"
  employee_type     = "full-time"
  manager           = "mwilliams"
  organisation_unit = "Platform Engineering"
  preferred_language = "en_US"

  userclass = ["employee", "vip"]
}
```

#### Опциональные поля — контактная информация:

| Поле                    | Тип              | Описание                                                                               |
| ----------------------- | ---------------- | -------------------------------------------------------------------------------------- |
| **`email_address`**     | `List of String` | Список адресов электронной почты пользователя. Первый адрес обычно считается основным. |
| **`telephone_numbers`** | `List of String` | Список стационарных телефонных номеров.                                                |
| **`mobile_numbers`**    | `List of String` | Список мобильных телефонных номеров.                                                   |
| **`street_address`**    | `String`         | Улица и номер дома.                                                                    |
| **`city`**              | `String`         | Город.                                                                                 |
| **`province`**          | `String`         | Область, штат или регион.                                                              |
| **`postal_code`**       | `String`         | Почтовый индекс.                                                                       |
| **`car_license`**       | `List of String` | Номера автомобилей пользователя. Используется редко, но поддерживается схемой FreeIPA. |

**Конфигурация с контактной информацией и адресом:**

```hcl
resource "freeipa_user" "contact_example" {
  name       = "bwayne"
  first_name = "Bruce"
  last_name  = "Wayne"

  email_address     = ["bruce.wayne@wayne.com", "b.wayne@example.com"]
  telephone_numbers = ["+1-555-100-2000"]
  mobile_numbers    = ["+1-555-999-8888"]
  street_address    = "1007 Mountain Drive"
  city              = "Gotham"
  province          = "New Jersey"
  postal_code       = "07001"
  car_license       = ["BAT-1"]
}
```

#### Read-Only поля:

|Поле|Тип|Описание|
|---|---|---|
|**`id`**|`String`|Уникальный идентификатор ресурса в состоянии Terraform. **Не задаётся вручную**, автоматически присваивается провайдером после создания пользователя

**Важные замечания:**

1. **Чувствительные данные**: Никогда не указывайте `userpassword` в виде plain-text в коде. Используйте `random_password = true` или передавайте пароль через переменные окружения / внешние системы управления секретами (Vault).
2. **Списковые поля**: `email_address`, `telephone_numbers`, `mobile_numbers`, `ssh_public_key`, `krb_principal_name`, `car_license`, `userclass` принимают **массив строк**. Для одного значения всё равно используйте синтаксис списка: `["value"]`.
3. **Формат дат**: Поля `krb_password_expiration` и `krb_principal_expiration` требуют строгого формата RFC3339: `YYYY-MM-DDTHH:MM:SSZ` (время в UTC).

### freeipa_group:

Группы в FreeIPA — это фундаментальный механизм для организации пользователей, управления доступом и назначения прав. Провайдер даёт возможность гибко управлять различными типами групп.

#### Обязательные поля:

|Поле|Тип|Описание|
|---|---|---|
|**`cn`**|`String`|**Имя группы** (Common Name). Это уникальный идентификатор группы в домене FreeIPA. Именно это имя используется при назначении прав, добавлении пользователей в группу и других операциях.|

**Базовая POSIX-группа:**

```hcl
resource "freeipa_group" "developers" {
  cn          = "developers"
  description = "Основная группа разработчиков"
}
```

**POSIX-группа с ручным указанием GID:**

Используется, когда требуется синхронизация GID с другими системами или миграция существующей инфраструктуры.

```hcl
resource "freeipa_group" "legacy_admins" {
  cn          = "legacy_admins"
  description = "Администраторы унаследованных систем"
  gidnumber   = 1500
}
```

**Не-POSIX группа для ролевого управления:**

Такие группы используются в правилах HBAC и sudo, где не требуются POSIX-атрибуты. Это более «чистый» способ для ролевого доступа.

```hcl
resource "freeipa_group" "sudo_web_admins" {
  cn          = "sudo_web_admins"
  description = "Группа для правил sudo веб-серверов"
  nonposix    = true
}
```

**Внешняя группа для интеграции с Active Directory:**

Позволяет включать пользователей из доверенного домена Active Directory в группы FreeIPA для централизованного управления доступом.

```hcl
resource "freeipa_group" "ad_engineers" {
  cn          = "ad_engineers"
  description = "Внешняя группа для инженеров из домена AD"
  external    = true
}
```
#### Опциональные поля:

| Поле              | Тип       | Описание                                                                                                                                                                                                                                                                                                          |
| ----------------- | --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`description`** | `String`  | Текстовое описание группы. Используется для документирования назначения группы, что особенно полезно при большом количестве групп в домене.                                                                                                                                                                       |
| **`gidnumber`**   | `Number`  | **Числовой идентификатор группы (GID)**. Позволяет задать GID вручную вместо автоматического назначения FreeIPA. Полезно при миграции с legacy-систем или для синхронизации с существующей инфраструктурой, где важны конкретные числовые идентификаторы. **Важно:** `gidnumber` применим только для POSIX-групп. |
| **`nonposix`**    | `Boolean` | **Создать группу как не-POSIX**. Если установлено `true`, группа не будет иметь GID и связанных с ним POSIX-атрибутов. Такие группы используются для ролевого управления доступом (RBAC), правил HBAC и sudo, а также для интеграции с доверенными доменами Active Directory.                                     |
| **`external`**    | `Boolean` | **Разрешить добавление внешних участников** из доверенных доменов (например, Active Directory). При установке `true` в группу можно добавлять пользователей и группы из доменов, с которыми настроены доверительные отношения (trust). Группа при этом автоматически становится не-POSIX.                         |

### freeipa_user_group_membership:

Этот ресурс управляет связью между пользователем и группой. **Важно:** он не создаёт ни пользователя, ни группу — оба объекта должны уже существовать в FreeIPA (или быть созданы в том же Terraform-проекте через `freeipa_user` и `freeipa_group`).

| Поле        | Тип      | Обязательное      | Описание                                                                                                                                                                   |
| ----------- | -------- | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`name`**  | `String` | **Да**            | Имя группы, в которую добавляется пользователь. Это поле является **обязательным идентификатором** ресурса. Именно по нему Terraform определяет, с какой группой работает. |
| **`user`**  | `String` | Нет               | Логин пользователя (`uid`), которого нужно добавить в группу.                                                                                                              |
| **`group`** | `String` | Нет               | Альтернативный способ указать группу. На практике чаще используется `name`, а `group` может применяться для ссылок на ресурс `freeipa_group`.                              |
| **`id`**    | `String` | Только для чтения | Уникальный идентификатор ресурса в состоянии Terraform. Автоматически формируется провайдером.                                                                             |

1. **Один ресурс — одно членство**: Каждый экземпляр `freeipa_user_group_membership` добавляет **одного** пользователя в **одну** группу. Для добавления пользователя в несколько групп нужно создать несколько ресурсов.
2. **Ссылки на ресурсы**: Рекомендуется использовать ссылки на атрибуты других ресурсов вместо хардкода строк, чтобы обеспечить правильный порядок создания и зависимости.

**Добавление пользователя в одну группу:**

```hcl
resource "freeipa_group" "developers" {
  cn = "developers"
}

resource "freeipa_user" "john" {
  name       = "jdoe"
  first_name = "John"
  last_name  = "Doe"
}

resource "freeipa_user_group_membership" "john_developer" {
  name = freeipa_group.developers.cn
  user = freeipa_user.john.name
}
```

**Добавление одного пользователя в несколько групп:**

```hcl
resource "freeipa_user" "alice" {
  name       = "asmith"
  first_name = "Alice"
  last_name  = "Smith"
}

resource "freeipa_group" "developers" {
  cn = "developers"
}

resource "freeipa_group" "admins" {
  cn = "admins"
}

resource "freeipa_group" "docker_users" {
  cn = "docker_users"
}

# Добавляем Алису в три разные группы
resource "freeipa_user_group_membership" "alice_developer" {
  name = freeipa_group.developers.cn
  user = freeipa_user.alice.name
}

resource "freeipa_user_group_membership" "alice_admin" {
  name = freeipa_group.admins.cn
  user = freeipa_user.alice.name
}

resource "freeipa_user_group_membership" "alice_docker" {
  name = freeipa_group.docker_users.cn
  user = freeipa_user.alice.name
}
```

**Массовое добавление пользователей с использованием `for_each`:**

```hcl
resource "freeipa_group" "engineering" {
  cn = "engineering"
}

# Список пользователей
locals {
  engineers = ["jsmith", "bwayne", "ckent"]
}

# Создаём пользователей
resource "freeipa_user" "engineer" {
  for_each   = toset(local.engineers)
  name       = each.key
  first_name = "Engineer"
  last_name  = each.key
}

# Добавляем каждого в группу engineering
resource "freeipa_user_group_membership" "engineer_membership" {
  for_each = toset(local.engineers)
  name     = freeipa_group.engineering.cn
  user     = freeipa_user.engineer[each.key].name
}
```

### freeipa_dns_zone:

Провайдер `camptocamp/freeipa` стремится отразить возможности API FreeIPA, поэтому многие поля напрямую соотносятся с параметрами команд `ipa dnszone-add` и `ipa dnszone-mod`. Учтите, что возможности провайдера Terraform могут быть уже, чем у Ansible-модуля `ipadnszone`, который поддерживает больше параметров

| Поле                           | Тип       | Описание                                                                                                                                           |
| ------------------------------ | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`zone_name`**                | `String`  | **Обязательное**. Имя DNS-зоны. **Критически важно:** имя должно заканчиваться точкой (`.`) — например, `example.com.`                             |
| **`skip_overlap_check`**       | `Boolean` | Позволяет принудительно создать зону, даже если она пересекается с уже существующей. По умолчанию `false`.                                         |
| **`skip_nameserver_check`**    | `Boolean` | Позволяет создать зону, даже если указанный nameserver не резолвится. По умолчанию `false`.                                                        |
| **`zone_forwarders`**          | `List`    | Список IP-адресов DNS-серверов, на которые будут пересылаться запросы. Например, `["8.8.8.8", "8.8.4.4"]`.                                         |
| **`forward_policy`**           | `String`  | Политика пересылки запросов. Может быть `only` (только forwarders), `first` (сначала forwarders, потом самостоятельно) или `none` (не пересылать). |
| **`authoritative_nameserver`** | `String`  | Основной DNS-сервер зоны (SOA MNAME). Например, `ns1.example.com.`.                                                                                |
| **`admin_email_address`**      | `String`  | Email администратора зоны (SOA RNAME). Например, `admin@example.com` (в конфигурации указывается с точкой вместо `@`, т.е. `admin.example.com`).   |
| **`allow_prt_sync`**           | `Boolean` | Разрешить автоматическую синхронизацию прямых (A, AAAA) и обратных (PTR) записей.                                                                  |
| **`dynamic_updates`**          | `Boolean` | Разрешить динамические обновления DNS.                                                                                                             |
| **`ttl`**                      | `Number`  | Время жизни (TTL) для записей зоны. Значение в секундах.                                                                                           |
| **`default_ttl`**              | `Number`  | TTL по умолчанию для записей, у которых он не указан явно.                                                                                         |
| **`soa_refresh`**              | `Number`  | Время обновления зоны (SOA REFRESH) в секундах.                                                                                                    |
| **`soa_retry`**                | `Number`  | Время повтора при ошибке (SOA RETRY) в секундах.                                                                                                   |
| **`soa_expire`**               | `Number`  | Время истечения срока действия (SOA EXPIRE) в секундах.                                                                                            |
| **`soa_minimum`**              | `Number`  | Время кэширования отрицательных ответов (SOA MINIMUM) в секундах.                                                                                  |

**Зона прямого просмотра:**

Пример показывает, как задать все ключевые параметры Start of Authority (SOA) записи:

```hcl
resource "freeipa_dns_zone" "example_zone" {
  zone_name = "example.com."
  authoritative_nameserver    = "ns1.example.com."
  admin_email_address    = "admin.example.com." # Точка вместо @
  ttl            = 3600
  default_ttl    = 1800
  soa_refresh        = 7200
  soa_retry          = 1800
  soa_expire         = 1209600
  soa_minimum        = 3600
  dynamic_update = true
}
```

**Зона с пересылкой запросов:**

Этот пример создает зону, которая все запросы перенаправляет на публичные DNS-серверы Google:

```hcl
resource "freeipa_dns_zone" "forward_zone" {
  zone_name      = "example.com."
  zone_forwarders     = ["8.8.8.8", "8.8.4.4"]
  forward_policy = "only"
}
```

**Зона обратного просмотра**

Для создания обратной зоны, которая используется для разрешения IP-адресов в имена, имя зоны должно быть сформировано специальным образом. Например, для сети `192.168.1.0/24`:

```hcl
resource "freeipa_dns_zone" "reverse_zone" {
  zone_name = "1.168.192.in-addr.arpa."
}
```

**Важные замечания:**

- **Имя зоны с точкой**: Всегда проверяйте, что `zone_name` заканчивается точкой. Это требование стандарта DNS, и FreeIPA строго его придерживается.
- **Создание обратных (PTR) записей**: Провайдер не создает PTR-записи автоматически при создании A-записей. Если они вам нужны, создайте обратную зону (как в Примере 3) и добавьте в нее PTR-запись с помощью `freeipa_dns_record`.

### freeipa_dns_record:

Ресурс `freeipa_dns_record` в провайдере `camptocamp/freeipa` — это инструмент для управления DNS-записями внутри домена FreeIPA. Он не предназначен для создания нескольких записей в классическом понимании (как массив ресурсов), но предоставляет гибкие возможности для управления как одиночными, так и множественными значениями для одного доменного имени, а также различными типами записей. Вот основные поля:

|Поле|Описание|Обязательное|
|---|---|---|
|`dnszoneidnsname`|Имя DNS-зоны в FreeIPA, в которой будет создана запись. **Важно:** имя зоны должно заканчиваться точкой (например, `example.com.`).|Да|
|`idnsname`|Имя самой DNS-записи (например, `www` для записи `www.example.com`).|Да|
|`type`|Тип DNS-записи. Определяет формат и назначение данных.|Да|
|`records`|Список (массив) значений для DNS-записи. Формат значения зависит от выбранного `type`.|Да|
|`dnsttl`|Время жизни записи в кэше (TTL) в секундах. Необязательное поле.|Нет|
**Создание записи типа A и AAAA с несколькими IP-адресами**

```hcl
resource "freeipa_dns_record" "web_server" {
  dnszoneidnsname = "example.com." # Зона обязательно с точкой на конце
  idnsname        = "web"
  type            = "A"
  records         = ["192.168.1.10", "192.168.1.11", "192.168.1.12"]
  dnsttl          = 3600
}

resource "freeipa_dns_record" "web_server_ipv6" {
  dnszoneidnsname = "example.com."
  idnsname        = "web"
  type            = "AAAA"
  records         = ["2001:db8::1", "2001:db8::2"]
}
```

**Создание псевдонима (CNAME):**

Для создания CNAME-записи, указывающей на каноническое имя, используйте тип `CNAME`. Массив `records` должен содержать только одно значение — целевое имя хоста

```hcl
resource "freeipa_dns_record" "www_alias" {
  dnszoneidnsname = "example.com."
  idnsname        = "www"
  type            = "CNAME"
  records         = ["webserver.example.com."]
}
```

**Создание почтовой записи (MX):**

MX-записи требуют особого формата: `priority domain`. Например, `10 mail.example.com.` означает приоритет 10 и почтовый сервер `mail.example.com.`

```hcl
resource "freeipa_dns_record" "mx_record" {
  dnszoneidnsname = "example.com."
  idnsname        = "@" # Запись для самой зоны
  type            = "MX"
  records         = ["10 mail.example.com.", "20 mail2.example.com."]
}
```

**Создание SRV-записи для сервисов:**

SRV-записи позволяют объявлять местоположение сервисов. Формат: `priority weight port target` (например, `10 50 88 ipa.example.com.`)

```hcl
resource "freeipa_dns_record" "ldap_srv" {
  dnszoneidnsname = "example.com."
  idnsname        = "_ldap._tcp"
  type            = "SRV"
  records         = ["10 50 389 ipa1.example.com.", "20 50 389 ipa2.example.com."]
}
```

**Создание TXT-записи:**

```hcl
resource "freeipa_dns_record" "spf_record" {
  dnszoneidnsname = "example.com."
  idnsname        = "@"
  type            = "TXT"
  records         = ["v=spf1 mx -all"]
}
```

**Создание обратных (PTR) записей:**

Провайдер не имеет отдельного флага для автоматического создания PTR-записей. Если вам нужна обратная запись, вы должны создать её явно, используя ресурс `freeipa_dns_record` в соответствующей зоне `in-addr.arpa`. Например, для IP `192.168.1.10`:

```hcl
resource "freeipa_dns_record" "ptr_record" {
  dnszoneidnsname = "1.168.192.in-addr.arpa." # Обратная зона
  idnsname        = "10" # Последний октет IP-адреса
  type            = "PTR"
  records         = ["webserver.example.com."]
}
```

##### Импорт существующих записей в домене:

**Как работает команда `terraform import`:**

Команда `terraform import` связывает ресурс из вашего конфигурационного файла с реально существующим объектом в FreeIPA. Она **не изменяет сам объект** и **не создает файл конфигурации за вас**. Её задача — просто добавить информацию об объекте в файл состояния Terraform (`terraform.tfstate`).

> **Важный нюанс для DNS-записей.** В отличие от некоторых других ресурсов, для импорта DNS-записи провайдеру `freeipa` нужно точно знать три вещи: **имя самой записи, имя зоны и тип записи**. Именно поэтому идентификатор формируется в виде одной строки с разделителями `/`: `"record_name/zone_name/record_type"`.

**Зачем нужен импорт на практике:**

1. **Переход к подходу «Инфраструктура как код» (IaC)**: У вас уже есть работающий домен FreeIPA с десятками DNS-записей, созданных через веб-интерфейс или командную строку. Вы решили перейти на управление через Terraform. Вместо того чтобы вручную удалять все записи и создавать их заново кодом (что рискованно), вы пишете конфигурацию Terraform для этих записей, а затем «импортируете» их. Terraform просто связывает свой код с существующими объектами, не внося в них никаких изменений.
2. **Аварийное восстановление или миграция**: Ваш код Terraform был утерян или повреждён, но инфраструктура продолжает работать. Вы можете написать новый код, описывающий текущее состояние ресурсов, и импортировать их, восстановив тем самым управление через Terraform.

**Пример импорта DNS-записи:**

Допустим, через веб-интерфейс FreeIPA вы создали A-запись `web` в зоне `example.com.`, которая указывает на `192.168.1.10`. Чтобы передать её под управление Terraform, выполните два шага.

**Шаг 1: Напишите конфигурацию ресурса в вашем `.tf` файле:**

Создайте ресурс `freeipa_dns_record`, который полностью соответствует импортируемой записи.

```hcl
resource "freeipa_dns_record" "web_server" {
  dnszoneidnsname = "example.com."
  idnsname        = "web"
  type            = "A"
  # На этом этапе поле 'records' можно оставить пустым или заполнить.
  # Terraform обновит его во время следующего 'plan' или 'apply'.
}
```

**Шаг 2: Выполните команду импорта:**

```hcl
# Синтаксис
terraform import <имя_ресурса_в_terraform> <идентификатор_ресурса_в_freeipa>

terraform import freeipa_dns_record.web_server web/example.com./A
```

После выполнения этой команды Terraform просканирует FreeIPA, найдет запись `web` типа `A` в зоне `example.com.` и свяжет её с ресурсом `freeipa_dns_record.web_server` в вашем коде.

Сразу после импорта обязательно выполните `terraform plan`. Terraform сравнит вашу конфигурацию с состоянием, которое он только что импортировал, и покажет различия. На этом этапе вы можете **дозаполнить конфигурационный файл**, добавив недостающие параметры (например, `records = ["192.168.1.10"]` и `dnsttl = 3600`), чтобы код полностью соответствовал реальному состоянию объекта. После того как `terraform plan` перестанет показывать изменения, ваша инфраструктура будет полностью описана кодом.
