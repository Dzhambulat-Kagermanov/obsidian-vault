## Введение

Операционная система (ОС) — это фундаментальный слой программного обеспечения, который абстрагирует аппаратные ресурсы компьютера и предоставляет унифицированный интерфейс для выполнения приложений. Для DevOps-инженера глубокое понимание принципов работы ОС критически важно: от диагностики проблем в production-среде до оптимизации контейнеризированных приложений и настройки инфраструктуры как кода.

> [!INFO] Связь с другими темами: Детальное управление процессами и ресурсами рассмотрено в [[11. Процессы и ресурсы| 11. Процессы и ресурсы]], работа с файловой системой — в [[1. Основы работы с дисками и файловыми системами| 9. Файловые системы и диски]], а загрузка системы и восстановление — в [[1. Unit файлы | 12. Systemd и загрузка]] и [[1. Модули ядра | 13. Ядро и восстановление]].


## 1. Архитектура ОС: Ядро и Пользовательское пространство

### Ring-модель и привилегии

Современные процессоры поддерживают уровни привилегий (rings). ОС использует два основных уровня:

- **Kernel Space (Ring 0)**: Полный доступ к аппаратному обеспечению, выполнение критических операций (управление памятью, планирование, драйверы).
- **User Space (Ring 3)**: Ограниченный доступ, приложения выполняются в изолированном окружении.

### Системные вызовы (syscalls)

Мост между user space и kernel space. Когда приложению нужен доступ к ресурсу (файл, сеть, память), оно вызывает syscall, который переключает процессор в kernel mode для выполнения операции.

```bash
# Просмотр системных вызовов в реальном времени
strace -p <PID>
# Пример: отслеживание открытия файла
strace ls /tmp 2>&1 | grep open
```

> [!TIP] Связь с контейнеризацией Контейнеры используют те же syscalls, что и хост-ОС, но изолируются через namespaces и cgroups. Это ключевое отличие от [[1. Виртуализация (VM) vs Контейнеризация | Виртуализация (VM) vs Контейнеризация]], где каждая VM имеет своё ядро.

## 2. Управление процессами

### Процесс vs Поток

- **Процесс**: Экземпляр программы с собственным адресным пространством, ресурсами и контекстом выполнения.
- **Поток (Thread)**: Легковесная единица выполнения внутри процесса, разделяющая память и ресурсы с другими потоками того же процесса.

### Жизненный цикл процесса

```mermaid
flowchart LR
New --> Ready
Ready --> Running
Running --> Waiting/Blocked
Waiting/Blocked --> Terminated
```

### Планировщик (Scheduler)

Отвечает за распределение процессорного времени. Основные алгоритмы:

- **CFS (Completely Fair Scheduler)** в Linux: использует "виртуальное время" для обеспечения справедливого распределения CPU.
- Приоритеты (nice value, RT-приоритеты) влияют на порядок выполнения.

> [!LINK] Детали Управление процессами, приоритизация и отладка подробно рассмотрены в [[11. Процессы и ресурсы | Процессы и ресурсы]].

## 3. Управление памятью

### Виртуальная память

Каждый процесс видит собственное непрерывное адресное пространство, которое отображается на физическую память через таблицу страниц (page table).

### Ключевые механизмы:

| Механизм       | Описание                                          | DevOps-применение                                                                                                         |
| -------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **Paging**     | Разбиение памяти на страницы (обычно 4KB)         | Понимание swap-активности при мониторинге                                                                                 |
| **Swap**       | Выгрузка неактивных страниц на диск               | Настройка `vm.swappiness` для оптимизации [[1. Основы работы с дисками и файловыми системами \|Файловые системы и диски]] |
| **MMU**        | Hardware-компонент для трансляции адресов         | Диагностика проблем с памятью через `dmesg`                                                                               |
| **OOM Killer** | Механизм завершения процессов при нехватке памяти | Настройка `oom_score_adj` для критичных сервисов                                                                          |

```bash
# Просмотр использования памяти
free -h
# Детальная информация о страницах
cat /proc/meminfo
# Мониторинг swap-активности
vmstat 1
```

## 4. Файловая система как абстракция

### VFS (Virtual File System)

Унифицированный интерфейс ядра для работы с разными типами ФС (ext4, XFS, NFS, procfs, sysfs).

### Inode и метаданные

Каждый файл описывается inode — структурой, содержащей:

- Права доступа (permissions)
- Владелец и группа (UID/GID)
- Размер, временные метки
- Указатели на блоки данных

```bash
# Просмотр inode
ls -li /path/to/file
# Статистика по inode
df -i
```

### Mount и namespaces

- **Mount**: Присоединение ФС к дереву каталогов.
- **Mount namespaces**: Изоляция точек монтирования — основа контейнеризации.

## 5. Ввод-Вывод (I/O) и устройства

### Блочные vs Символьные устройства

- **Блочные** (`/dev/sda`): Доступ по блокам, буферизация, кэширование.
- **Символьные** (`/dev/tty`): Потоковый доступ, без буферизации.

### I/O Schedulers

Алгоритмы планирования дисковых операций:

- `mq-deadline`, `kyber`, `bfq` — выбор зависит от типа нагрузки (SSD/HDD, база данных/веб-сервер).

```bash
# Просмотр текущего планировщика
cat /sys/block/sda/queue/scheduler
# Мониторинг I/O
iostat -x 1
```

> [!TIP] Оптимизация Для баз данных ([[Synced/DevOps/Базы данных и хранилища/1. Реляционные СУБД (OLTP)/1. PostgreSQL/1. Архитектура|PostgreSQL]], [[1. Архитектура движков хранения|MySQL]]) часто рекомендуется `deadline` или `noop` на SSD.

## 6. Модель безопасности ОС

### Пользователи, группы, права

- **DAC (Discretionary Access Control)**: Классическая модель `rwx` для user/group/others.
- **SUID/SGID**: Специальные биты для выполнения с правами владельца/группы файла.

### Расширенные механизмы

| Механизм             | Назначение                     | Пример использования                                             |
| -------------------- | ------------------------------ | ---------------------------------------------------------------- |
| **Capabilities**     | Дробление root-привилегий      | `CAP_NET_BIND_SERVICE` для привязки к порту <1024 без root       |
| **SELinux/AppArmor** | Mandatory Access Control (MAC) | Изоляция сервисов в [[1. SELinux, AppArmor\|Безопасность хоста]] |
| **Namespaces**       | Изоляция ресурсов              | Основа контейнеров: PID, network, mount, UTS, IPC, user          |
| **Cgroups**          | Ограничение ресурсов           | Контроль CPU/memory для сервисов и контейнеров                   |

```bash
# Просмотр capabilities процесса
capsh --print
# Проверка контекста SELinux
ls -Z /path/to/file
```

## 7. Загрузка системы: от BIOS до user space

```mermaid
graph LR
    A[BIOS/UEFI] --> B[Bootloader GRUB2]
    B --> C[Ядро Linux + initramfs]
    C --> D[systemd/init]
    D --> E[Multi-user.target]
```

### Ключевые этапы:

1. **Bootloader**: Загрузка ядра и initramfs (временная ФС с драйверами).
2. **Ядро**: Инициализация оборудования, монтирование root ФС.
3. **Init (systemd)**: Запуск юнитов, достижение целевого состояния (`target`).

> [!LINK] Детали загрузки Настройка GRUB2, восстановление после сбоев — в [[1. Модули ядра|Ядро и восстановление]]. Управление systemd — в [[1. Unit файлы|Systemd и загрузка]].

## 8. Межпроцессное взаимодействие (IPC)

| Механизм           | Описание                             | Use-case                                     |
| ------------------ | ------------------------------------ | -------------------------------------------- |
| **Pipes/FIFOs**    | Однонаправленный поток данных        | Связь родитель-потомок, shell-пайплайны      |
| **Sockets**        | Сетевое или локальное взаимодействие | Микросервисы, [[Брокеры сообщений]]          |
| **Shared Memory**  | Общая область памяти                 | Высокопроизводительный обмен данными         |
| **Message Queues** | Структурированные сообщения          | Асинхронная коммуникация                     |
| **Signals**        | Асинхронные уведомления              | Управление процессами (`SIGTERM`, `SIGKILL`) |

```bash
# Просмотр IPC-объектов
ipcs -a
# Отправка сигнала
kill -SIGTERM <PID>
```

## 9. Практическое значение для DevOps

1. **Контейнеризация**: Понимание namespaces/cgroups необходимо для отладки Docker/Podman ([[Docker/Архитектура.md]]).
2. **Мониторинг**: Метрики CPU, memory, I/O интерпретируются через призму механизмов ОС ([[Node Exporter.md]], [[Ключевые метрики.md]]).
3. **Безопасность**: Hardening ОС, настройка SELinux, управление привилегиями ([[15. Безопасность хоста.md]]).
4. **Производительность**: Tuning ядра (`sysctl`), выбор I/O scheduler, оптимизация памяти.
5. **Troubleshooting**: Анализ логов (`journalctl`), трассировка syscalls (`strace`), диагностика OOM.

> [!EXAMPLE] Сценарий: Высокая загрузка CPU
> 1. `top`/`htop` → определение процесса
> 2. `pidstat -p <PID> 1` → детализация по потокам
> 3. `strace -p <PID>` → анализ syscalls
> 4. `perf top` → профилирование на уровне ядра
> 5. Проверка [[6. Мониторинг|Мониторинг]] и [[1. journald, rsyslog, logrotate|Логирование и аудит]]
