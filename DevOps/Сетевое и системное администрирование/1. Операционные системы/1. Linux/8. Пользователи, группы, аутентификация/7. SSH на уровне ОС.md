## Введение

**SSH (Secure Shell)** — это фундаментальный протокол удаленного администрирования Linux-систем. Практически каждое действие DevOps-инженера на удаленном сервере начинается с SSH-подключения: деплой кода, настройка сервисов, диагностика проблем, управление конфигурациями через Ansible.

Для DevOps-инженера глубокое понимание SSH критично по нескольким причинам:

- Это основной способ доступа к production-серверам
- Через SSH-туннели проксируются подключения к базам данных и внутренним сервисам
- SSH-ключи используются для аутентификации в Git, CI/CD, Ansible
- Неправильная настройка SSH — одна из самых частых причин компрометации серверов

## 1. Архитектура SSH: клиент-серверная модель

### Общая схема работы

```mermaid
sequenceDiagram
    participant Client as "Клиент (ssh)"
    participant Network as "Сеть (TCP порт 22)"
    participant Server as "Сервер (sshd)"
    participant PAM as "PAM"
    participant Shell as "Оболочка (bash)"
    
    Client->>Network: 1. TCP handshake (SYN/SYN-ACK/ACK)
    Network->>Server: 2. Соединение установлено
    Server->>Client: 3. Отправка версии протокола и host key
    Client->>Server: 4. Согласование алгоритмов шифрования (Key Exchange)
    Server->>Client: 5. Установка зашифрованного канала
    Client->>Server: 6. Аутентификация (ключ/пароль)
    Server->>PAM: 7. Проверка через PAM (если пароль)
    PAM-->>Server: 8. PAM_SUCCESS
    Server->>Shell: 9. Запуск оболочки пользователя
    Shell-->>Client: 10. Интерактивная сессия (зашифрована)
```
