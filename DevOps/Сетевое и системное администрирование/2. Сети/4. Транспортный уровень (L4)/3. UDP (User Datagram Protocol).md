+---Архитектура и заголовок UDP
|   |   |   |       Структура заголовка UDP: source port, destination port, length, checksum.
|   |   |   |       Простота: минимальный overhead (8 байт заголовок).
|   |   |   |       Отсутствие гарантий: нет установки соединения, нет подтверждений, нет контроля потока.
|   |   |   |       Checksum: опциональный в IPv4, обязательный в IPv6.
|   |   |   |
|   |   |   +---Сценарии использования UDP
|   |   |   |       DNS: запросы и ответы (порт 53).
|   |   |   |       DHCP: DORA процесс (порты 67, 68).
|   |   |   |       SNMP: мониторинг устройств (порт 161).
|   |   |   |       NTP: синхронизация времени (порт 123).
|   |   |   |       TFTP: простая передача файлов (порт 69).
|   |   |   |       VoIP (RTP): голосовой трафик (динамические порты).
|   |   |   |       Streaming: видео и аудио потоки.
|   |   |   |       Игры: онлайн-игры с низкой задержкой.
|   |   |   |       Traceroute: использование UDP или ICMP.
|   |   |   |
|   |   |   +---Проблемы и решения
|   |   |   |       Потеря пакетов: как приложения обрабатывают (retry, forward error correction).
|   |   |   |       Дубликаты: обработка на уровне приложения.
|   |   |   |       Переупорядочивание: обработка на уровне приложения.
|   |   |   |       MTU и фрагментация: проблемы с большими UDP-дейтаграммами, Path MTU Discovery.
|   |   |   |       UDP Lite: поддержка частичных checksum (RFC 3828).
|   |   |   |
|   |   |   \---UDP в Linux
|   |   |           Socket API: `SOCK_DGRAM`.
|   |   |           Multicast: присоединение к multicast-группам (`IP_ADD_MEMBERSHIP`).
|   |   |           Broadcast: отправка широковещательных сообщений.
|   |   |           Raw sockets: доступ к сырым UDP-пакетам.
