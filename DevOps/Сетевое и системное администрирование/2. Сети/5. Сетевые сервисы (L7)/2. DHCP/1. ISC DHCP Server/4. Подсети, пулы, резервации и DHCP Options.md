## 1. Подсети и области выдачи адресов

**Подсеть (`subnet`)** — диапазон IP-адресов с общей сетевой маской, для которого DHCP-сервер определяет правила выдачи адресов.

В ISC DHCP подсеть описывается блоком `subnet` в файле `/etc/dhcp/dhcpd.conf`:

```conf
subnet 192.168.10.0 netmask 255.255.255.0 {
    range 192.168.10.100 192.168.10.200;
}
```

- `subnet` и `netmask` определяют обслуживаемую IPv4-подсеть.
- `range` задаёт адреса, доступные для **динамической** выдачи.
- Адреса вне `range` не выдаются из этого динамического пула; их можно использовать для серверов, маршрутизаторов и статических привязок, если они не заняты и не конфликтуют с другими правилами.

**Важно:** блок `subnet` не создаёт сетевой интерфейс, VLAN или маршрут. Он описывает правила DHCP для уже существующей сети. О сетевой адресации подробнее см. профильный раздел L3 в базе знаний.

## 2. Пулы адресов и исключения

**Пул (`pool`)** — набор адресов, из которого сервер выбирает адрес для клиента. Для обычной конфигурации достаточно директивы `range` внутри `subnet`.

```conf
subnet 192.168.10.0 netmask 255.255.255.0 {
    range 192.168.10.100 192.168.10.150;
    range 192.168.10.170 192.168.10.200;
}
```

В этом примере диапазон `192.168.10.151–192.168.10.169` не входит в динамические диапазоны. Отдельной директивы `exclude` для такого случая не требуется: **исключение достигается выбором границ `range`**.

Не включайте в динамический диапазон адрес шлюза, адрес самого DHCP-сервера и адреса устройств со статической настройкой. Иначе возможны конфликты IP-адресов.

Блок `pool { ... }` нужен для более сложных правил выбора клиентов (например, классов); для обычного разделения адресов он не обязателен.

## 3. Резервации адресов (`host`)

**Резервация** — правило, связывающее определённый DHCP-клиент с заданным IP-адресом. В простом сценарии клиент определяется по MAC-адресу сетевого интерфейса.

```conf
host printer01 {
    hardware ethernet 52:54:00:12:34:56;
    fixed-address 192.168.10.20;
}
```

- `host printer01` — локальное имя записи в конфигурации `dhcpd`; это не автоматическое создание DNS-записи.
- `hardware ethernet` — MAC-адрес клиента.
- `fixed-address` — адрес, предлагаемый этому клиенту.

Для предсказуемой конфигурации зарезервированный адрес `192.168.10.20` находится **в пределах подсети, но вне динамического диапазона** `192.168.10.100–192.168.10.200`.

> [!warning] Важное ограничение
> MAC-адрес не является надёжным средством аутентификации: его можно изменить или подменить. Резервация обеспечивает удобство адресации, но не защиту доступа. Кроме того, поведение идентификации клиента может зависеть от DHCP Client Identifier (Option 61), поэтому при сложных клиентах необходимо проверять фактические запросы и записи аренд.

## 4. DHCP Options

**DHCP Options** — дополнительные параметры, которые сервер передаёт клиенту вместе с адресом. Они позволяют автоматически сообщить шлюз, DNS-серверы и другие сетевые настройки.

```conf
subnet 192.168.10.0 netmask 255.255.255.0 {
    range 192.168.10.100 192.168.10.200;

    option routers 192.168.10.1;
    option subnet-mask 255.255.255.0;
    option domain-name-servers 192.168.10.10, 192.168.10.11;
    option domain-name "lab.example";
}
```

| Директива ISC DHCP | Назначение | DHCPv4 Option |
|---|---|---|
| `option subnet-mask` | Маска подсети | 1 |
| `option routers` | Шлюз по умолчанию | 3 |
| `option domain-name-servers` | Адреса DNS-серверов | 6 |
| `option domain-name` | DNS-домен клиента | 15 |
| `option ntp-servers` | Серверы времени (при поддержке клиентом) | 42 |
| `option domain-search` | Список доменов поиска (при поддержке клиентом) | 119 |

DHCP передаёт параметры, но **не гарантирует**, что каждый клиент применит все Options: это зависит от операционной системы и DHCP-клиента.

## 5. Срок аренды адреса

В ISC DHCP продолжительность аренды обычно задаётся в секундах:

```conf
default-lease-time 3600;
max-lease-time 7200;
```

- `default-lease-time 3600` — типовой срок аренды 1 час, если клиент не запросил иной срок.
- `max-lease-time 7200` — верхний предел аренды 2 часа, который сервер готов предоставить.

Эти директивы можно задавать глобально либо в подходящем блоке конфигурации. Подробный жизненный цикл аренды, T1 и T2 рассмотрен в отдельной теоретической заметке; здесь важно только то, что срок аренды влияет на частоту продлений и скорость повторного использования адресов.

## 6. Несколько подсетей на одном DHCP-сервере

Один `dhcpd` может обслуживать несколько IPv4-подсетей. Для каждой задаются собственные диапазоны и параметры:

```conf
authoritative;
default-lease-time 3600;
max-lease-time 7200;

subnet 192.168.10.0 netmask 255.255.255.0 {
    range 192.168.10.100 192.168.10.200;
    option routers 192.168.10.1;
    option subnet-mask 255.255.255.0;
    option domain-name-servers 192.168.10.10;
}

subnet 192.168.20.0 netmask 255.255.255.0 {
    range 192.168.20.100 192.168.20.200;
    option routers 192.168.20.1;
    option subnet-mask 255.255.255.0;
    option domain-name-servers 192.168.10.10;
}

host printer01 {
    hardware ethernet 52:54:00:12:34:56;
    fixed-address 192.168.10.20;
}
```

**Как сервер выбирает нужную подсеть:**

- При непосредственном получении запроса на локальном интерфейсе учитывается сеть интерфейса.
- При получении запроса через DHCP Relay сервер обычно использует поле `giaddr` для выбора подходящей подсети.

Наличие двух блоков `subnet` **само по себе не обеспечивает передачу DHCP между VLAN**. Для удалённой подсети необходим корректно настроенный DHCP Relay и маршрутизация. Подробнее: [[Synced/DevOps/Сетевое и системное администрирование/2. Сети/5. Сетевые сервисы (L7)/2. DHCP/0. Теория и принципы работы/4. DHCP Relay и работа между подсетями.md|DHCP Relay и работа между подсетями]].

> [!note] О директиве `authoritative`
> Она объявляет сервер авторитетным для обслуживаемых сетей и позволяет ему отвечать DHCPNAK на некорректные запросы клиентов. Используйте её только там, где этот DHCP-сервер действительно должен обслуживать соответствующую сеть.

## 7. Проверка конфигурации и выданных адресов

После изменения `/etc/dhcp/dhcpd.conf` сначала проверьте синтаксис:

```bash
sudo dhcpd -t -4 -cf /etc/dhcp/dhcpd.conf
```

Если ошибок нет, перезапустите службу:

```bash
sudo systemctl restart isc-dhcp-server
```

Проверьте её состояние и последние сообщения:

```bash
systemctl status isc-dhcp-server
sudo journalctl -u isc-dhcp-server -n 30 --no-pager
```

Посмотрите текущую базу аренд:

```bash
sudo less /var/lib/dhcp/dhcpd.leases
```

Файл `dhcpd.leases` — рабочая база состояния ISC DHCP, **не редактируйте его вручную** при обычной эксплуатации. Для проверки резервации сопоставьте MAC-адрес клиента с записью `host`, а затем проверьте фактически полученный адрес на клиенте.

Если клиент не получает адрес, проверяйте в таком порядке: работает ли служба; слушает ли она нужный интерфейс; соответствует ли запрос обслуживаемой подсети; остались ли свободные адреса; корректен ли DHCP Relay (если используется). Подробная диагностика вынесена в отдельную заметку цикла.

## 8. Глоссарий

| Термин | Определение |
|---|---|
| **Subnet** | Подсеть, для которой сервер определяет правила DHCP-обслуживания. |
| **Scope** | Логическая область адресов и параметров DHCP; в ISC DHCP обычно описывается через `subnet` и связанные директивы. |
| **Range** | Непрерывный диапазон адресов для динамической выдачи. |
| **Pool** | Набор адресов, предназначенных для выдачи определённым клиентам по правилам сервера. |
| **Reservation** | Закрепление определённого IP-адреса за конкретным DHCP-клиентом. |
| **DHCP Option** | Дополнительный параметр конфигурации, передаваемый DHCP-клиенту. |
| **Lease** | Аренда IP-адреса на ограниченный срок. |
| **DHCP Relay** | Посредник, пересылающий DHCP-сообщения между разными сетями. |
| **`giaddr`** | Поле DHCPv4, содержащее адрес relay-агента, используемый в том числе для выбора подсети. |
| **`dhcpd.conf`** | Основной конфигурационный файл ISC DHCP Server. |

## Итоги — что было разобрано

- Блок `subnet` определяет обслуживаемую сеть, а `range` — адреса для динамической выдачи.
- Исключения реализуются правильным выбором диапазонов; резервации задаются блоками `host`.
- DHCP Options передают клиентам сетевые параметры, но применение зависит от клиента.
- Один ISC DHCP Server может обслуживать несколько подсетей; между VLAN обычно требуется DHCP Relay.
- После изменения конфигурации необходимо проверить синтаксис, перезапустить службу и просмотреть журнал.
