## 1. Для чего нужен язык выражений

**Выражение (`expression`)** — конструкция, которая вычисляет значение: строку байтов, число, логический результат или адрес. В `dhcpd.conf` выражения позволяют использовать **данные конкретного DHCP-запроса**, а не только статические параметры.

Основные задачи:

- определить тип клиента по Option 60 или Option 93;
- получить часть идентификатора через `substring()`;
- собрать имя из нескольких фрагментов через `concat()`;
- преобразовать двоичные данные в читаемый текст;
- выбрать первое доступное значение из нескольких источников;
- задать значение переменной и использовать его в дальнейших операторах.

Пример простого условия:

```dhcpd
if substring(option vendor-class-identifier, 0, 9) = "PXEClient" {
    option host-name "network-boot-client";
}
```

Сервер извлекает первые девять байтов Option 60, сравнивает их со строкой `PXEClient` и при совпадении задает DHCP Option 12. **Это не меняет hostname операционной системы напрямую**: клиент вправе проигнорировать присланную опцию.

## 2. Где разрешены выражения и когда они вычисляются

В `dhcpd.conf` важно различать **описание правила** и **исполнение правила**.

| Конструкция | Назначение | Пример |
|---|---|---|
| `match if` | Определить принадлежность к классу | `match if option vendor-class-identifier = "LAB";` |
| `match` | Получить ключ для поиска `subclass` | `match hardware;` |
| `if` / `elsif` / `else` | Условно выполнить операторы | `if exists host-name { ... }` |
| `set` | Присвоить значение переменной | `set label = "lab";` |
| `option` с выражением | Вычислить отправляемый параметр | `option host-name = concat("pc-", "01");` |
| `on commit` / `on release` / `on expiry` | Выполнить действия при событии аренды | `on commit { ... }` |

> [!warning] Не путать этапы обработки
> Классификация клиентов выполняется раньше обычных исполняемых операторов. Поэтому `match if` не следует строить на переменной, которую предполагается предварительно создать оператором `set` в том же запросе. Кроме того, не каждое выражение доступно в каждом контексте: некоторые значения имеют смысл только при обработке аренды или события.

Области действия параметров и их наследование описаны отдельно: [[Synced/DevOps/Сетевое и системное администрирование/2. Сети/5. Сетевые сервисы (L7)/2. DHCP/1. ISC DHCP Server/3. Структура dhcpd.conf, области действия и наследование.md|Структура dhcpd.conf, области действия и наследование]].

## 3. Типы данных и представление значений

Для правильной работы выражений необходимо различать **текст** и **набор байтов**.

```dhcpd
"LAB"             # ASCII-строка из трех байтов
4c:41:42          # те же три байта в шестнадцатеричном виде
"10.0.0.5"        # текст, НЕ IP-адрес в двоичном формате
10.0.0.5         # литерал IP-адреса там, где ожидается адрес
1:aa:bb:cc:dd:ee:ff  # тип Ethernet + MAC, семь байтов
```

Сравнение обычно выполняется по содержимому и длине последовательности байтов. Регистр букв, лишний нулевой байт и разделители могут изменить результат.

**Пример:** `hardware` включает байт типа аппаратного адреса. Для Ethernet он равен `01`, поэтому результат отличается от шести байтов MAC, полученных через `substring(hardware, 1, 6)`.

## 4. Доступ к данным DHCP-запроса

### 4.1. `option` — значение DHCP Option

```dhcpd
option vendor-class-identifier
option dhcp-client-identifier
option host-name
```

В выражении `option имя` означает **полученное от клиента значение соответствующей опции**, если она присутствует. Не следует путать это с оператором `option имя значение;`, который **задает параметр для отправки**.

```dhcpd
if exists host-name {
    set requested_name = option host-name;
}
```

`exists` проверяет присутствие опции. Это надежнее, чем предполагать, что она отправляется каждым клиентом.

### 4.2. `hardware` — аппаратный адрес и тип оборудования

```dhcpd
set client_hardware = hardware;
set client_mac = substring(hardware, 1, 6);
```

Для обычного Ethernet первый байт `hardware` — тип `01`, следующие шесть байтов — MAC. **Не все DHCP-клиенты обязаны использовать Ethernet или шестибайтовый адрес**, поэтому пример с длиной `6` не является универсальным.

### 4.3. `leased-address` — назначенный IP-адрес

`leased-address` предоставляет адрес аренды в контекстах, где он определен. Особенно полезен в обработчиках событий:

```dhcpd
on commit {
    set ip_text = binary-to-ascii(10, 8, ".", leased-address);
}
```

Здесь IP переводится в текстовую десятичную запись. Само присвоение **не обновляет DNS** и не вызывает внешние программы.

### 4.4. `packet`, `suffix`, `substring` и служебные данные

В ISC DHCP доступны выражения для извлечения данных из пакета и значения, связанные с обработкой клиента. Однако обращаться к ним нужно только в предусмотренных документацией контекстах; не следует предполагать, что все поля доступны на любой стадии.

## 5. `substring()` — извлечение части значения

**Синтаксис:** `substring(данные, смещение, длина)`.

```dhcpd
substring(option vendor-class-identifier, 0, 9)
```

- `данные` — исходная последовательность байтов;
- `смещение` — индекс первого байта, отсчет с нуля;
- `длина` — максимальное число извлекаемых байтов.

**Пример PXE:**

```dhcpd
class "pxe-clients" {
    match if substring(option vendor-class-identifier, 0, 9) = "PXEClient";
}
```

Option 60 у PXE-клиента часто начинается с `PXEClient`, но затем содержит дополнительную информацию. Поэтому сравнение префикса полезнее проверки всей строки.

**Пример MAC без типа оборудования:**

```dhcpd
set mac_bytes = substring(hardware, 1, 6);
```

Это извлекает именно шесть байтов, а не строку вида `aa:bb:cc:dd:ee:ff`.

## 6. `concat()` — объединение последовательностей байтов

**Синтаксис:** `concat(значение1, значение2, ...)`.

```dhcpd
set label = concat("lab-", "pc-", "01");
```

Результат: `lab-pc-01`.

`concat()` **не вставляет разделители автоматически**. Если между частями нужны точка, дефис или двоеточие, их необходимо указать явно.

Пример составного ключа для класса:

```dhcpd
class "vendor-and-mac" {
    match concat(hardware, "|", option vendor-class-identifier);
}
```

При использовании `subclass` вторым аргументом будет **единая байтовая константа**, равная результату `concat()`, а не отдельный набор параметров. Подробности — в [[Synced/DevOps/Сетевое и системное администрирование/2. Сети/5. Сетевые сервисы (L7)/2. DHCP/1. ISC DHCP Server/6. Классы клиентов и условная выдача параметров.md|Классы клиентов и условная выдача параметров]].

## 7. `binary-to-ascii()` — преобразование байтов в текст

**Синтаксис:** `binary-to-ascii(основание, ширина, разделитель, данные)`.

- **Основание** — система счисления, например `10` или `16`.
- **Ширина** — количество битов в одной обрабатываемой группе, обычно `8` для байтов.
- **Разделитель** — строка между числами.
- **Данные** — исходная последовательность байтов.

Пример для IP-адреса:

```dhcpd
set ip_text = binary-to-ascii(10, 8, ".", leased-address);
```

Для адреса `192.168.50.101` результатом будет текст `192.168.50.101`.

Пример для MAC:

```dhcpd
set mac_text = binary-to-ascii(16, 8, ":", substring(hardware, 1, 6));
```

Результат — шестнадцатеричные компоненты, разделенные двоеточиями. **Не следует предполагать обязательное дополнение каждого компонента ведущим нулем**: например, `a` вместо `0a` может оказаться нормальным результатом. Для автоматического формирования DNS-имен это важно.

## 8. `pick-first-value()` — первое непустое значение

**Синтаксис:** `pick-first-value(выражение1, выражение2, ...)`.

Функция возвращает первое значение, которое существует и не является пустым. Ее удобно применять при выборе имени клиента из нескольких источников.

```dhcpd
set client_name = pick-first-value(
    option host-name,
    concat("host-", binary-to-ascii(10, 8, "-", substring(hardware, 1, 6)))
);
```

Если клиент передал непустую Option 12, будет выбрано ее значение. Иначе сервер сформирует имя на основе MAC. Это **только значение переменной**; чтобы использовать его для DDNS или отправки опции, нужны дополнительные операторы.

> [!warning] Доверие к именам
> DHCP Option 12 передается самим клиентом и может содержать произвольные данные. Для DNS-имен необходимы проверка допустимых символов, ограничение длины и продуманная политика коллизий. Прямое использование имени клиента в скриптах или DNS без валидации опасно.

## 9. Логические выражения и сравнения

Условия в `dhcpd.conf` используют операторы сравнения и логические связки:

```dhcpd
if exists vendor-class-identifier and
   substring(option vendor-class-identifier, 0, 9) = "PXEClient" {
    option host-name "pxe-device";
}
```

Типичные элементы:

| Элемент | Значение |
|---|---|
| `=` | Равенство |
| `!=` | Неравенство |
| `and` | Логическое И |
| `or` | Логическое ИЛИ |
| `not` | Логическое НЕ |
| `exists option-name` | Проверка присутствия опции |
| `known` | Признак известного клиента в поддерживаемом контексте |

Используйте скобки при комбинировании условий, чтобы явно задавать группировку. Сложные условия лучше разбивать на несколько простых проверок — это облегчает сопровождение.

## 10. `set` и переменные

**`set`** присваивает переменной результат выражения:

```dhcpd
set device_prefix = "lab";
set device_name = concat(device_prefix, "-pc01");
option host-name = device_name;
```

**Важное различие:** переменная — промежуточное значение, а DHCP Option — параметр, который сервер может передать клиенту. Команда `set` сама по себе ничего не отправляет.

В исполняемых выражениях также применяется `unset` для удаления значения переменной в поддерживаемом контексте.

Не путайте переменные `set` с глобальными параметрами `default-lease-time`, `max-lease-time` и т. п.: это разные элементы языка конфигурации.

### Когда использовать переменные

- когда длинное выражение применяется несколько раз;
- когда нужно последовательно собрать значение;
- когда выражение должно быть понятным при диагностике;
- в обработчиках событий аренды, где несколько параметров передаются внешней системе.

## 11. `if`, `elsif`, `else` — условная логика

```dhcpd
if exists vendor-class-identifier {
    if substring(option vendor-class-identifier, 0, 9) = "PXEClient" {
        option host-name "pxe-client";
    } else {
        option host-name "ordinary-client";
    }
} else {
    option host-name "unknown-client";
}
```

Сначала проверяется наличие Option 60, затем ее содержимое. Это пример вычисления отправляемой опции, **не правила выдачи адреса**.

`if` удобен для небольших локальных ветвлений; при большом числе устройств с общими признаками обычно лучше выделить `class` и правила `pool`.

## 12. Сборка имени из MAC: полный разбор

Рассмотрим выражение, похожее на встречающееся в рабочих конфигурациях:

```dhcpd
set generated_name = concat(
    "host-",
    binary-to-ascii(10, 8, "-", substring(hardware, 1, 6))
);
```

Предположим, `hardware` равно `01:aa:bb:cc:dd:ee:ff`.

| Шаг | Выражение | Результат |
|---|---|---|
| 1 | `hardware` | `01:aa:bb:cc:dd:ee:ff` |
| 2 | `substring(hardware, 1, 6)` | `aa:bb:cc:dd:ee:ff` (шесть байтов) |
| 3 | `binary-to-ascii(10, 8, "-", ...)` | `170-187-204-221-238-255` |
| 4 | `concat("host-", ...)` | `host-170-187-204-221-238-255` |
| 5 | `set generated_name = ...` | Значение сохранено в переменной |

Здесь основание `10` означает **десятичное представление байтов MAC**, а не привычную шестнадцатеричную запись. Это не ошибка, но результат часто удивляет администратора.

Если требуется передать сформированное имя клиенту:

```dhcpd
option host-name = generated_name;
```

Если требуется **зарегистрировать его в DNS**, одного выражения недостаточно. Нужны DDNS-настройки и политика обновлений, рассмотренные в [[Synced/DevOps/Сетевое и системное администрирование/2. Сети/5. Сетевые сервисы (L7)/2. DHCP/1. ISC DHCP Server/9. Dynamic DNS и интеграция с DNS.md|Dynamic DNS и интеграция с DNS]].

## 13. Другие полезные функции и выражения

| Конструкция                   | Для чего нужна                           | Замечание                                           |
| ----------------------------- | ---------------------------------------- | --------------------------------------------------- |
| `suffix(данные, длина)`       | Последние байты значения                 | В отличие от `substring()`, отсчет идет от конца    |
| `lcase(данные)`               | Перевод ASCII-букв в нижний регистр      | Полезно при нормализации текста                     |
| `ucase(данные)`               | Перевод ASCII-букв в верхний регистр     | Не универсальная Unicode-нормализация               |
| `encode-int(число, ширина)`   | Преобразование целого числа в байты      | Ширина задается в битах                             |
| `extract-int(данные, ширина)` | Извлечение числа из байтов               | Важно учитывать формат исходных данных              |
| `reverse(ширина, данные)`     | Разворот порядка групп битов             | Используется в специализированных преобразованиях   |

Примеры:

```dhcpd
set short_id = suffix(option dhcp-client-identifier, 4);
set normalized = lcase(option host-name);
```

Оба выражения имеют смысл только когда соответствующие клиентские опции присутствуют. При использовании в рабочем коде добавляйте проверки `exists` или предусмотренные запасные значения.

## 14. Выражения и обработчики событий аренды

Выражения часто используются внутри `on commit`, `on release` и `on expiry`, например для вычисления адреса и имени перед обновлением внешней системы:

```dhcpd
on commit {
    set ip_text = binary-to-ascii(10, 8, ".", leased-address);
    set mac_text = binary-to-ascii(16, 8, ":", substring(hardware, 1, 6));
}
```

Этот блок показывает только **вычисление значений**. Он не запускает программу, не записывает лог и не обновляет DNS. Вопросы вызова скриптов, доступности `execute()` в конкретной сборке, обработки ошибок и событий рассматриваются отдельно: [[Synced/DevOps/Сетевое и системное администрирование/2. Сети/5. Сетевые сервисы (L7)/2. DHCP/1. ISC DHCP Server/8. Обработчики событий и выполнение скриптов.md|Обработчики событий и выполнение скриптов]].

## 15. Диагностика выражений

### 15.1. Проверка синтаксиса

```bash
sudo dhcpd -t -cf /etc/dhcp/dhcpd.conf
```

Проверка обнаруживает ошибки разбора конфигурации, но **не гарантирует**, что условие совпадет с реальными клиентскими данными.

### 15.2. Просмотр входящих DHCP-пакетов

```bash
sudo tcpdump -ni any -vvv -s0 'udp port 67 or udp port 68'
```

Сравните реальные Option 60, 61, 82, 93 и MAC с ожидаемым форматом. Не все опции присутствуют в каждом пакете.

### 15.3. Типичные ошибки

| Симптом | Возможная причина | Что проверить |
|---|---|---|
| Условие по MAC не совпадает | `hardware` содержит байт типа | Сравниваемые байты и `substring(hardware, 1, 6)` |
| PXE-клиент не попал в класс | Option 60 длиннее `PXEClient` | Сравнение префикса, а не полной строки |
| Имя из MAC выглядит как числа | Использовано основание `10` | Нужно ли десятичное или шестнадцатеричное представление |
| `pick-first-value` выбрал не то имя | Первая опция непустая, но нежелательная | Порядок аргументов и валидацию |
| Условие всегда ложно | Отсутствует опция или неверное смещение | `exists`, фактические байты в `tcpdump` |
| Переменная не видна в `match if` | Она задается позднее через `set` | Этап классификации и контекст исполнения |
| `dhcpd -t` успешен, но клиент получает не те параметры | Логическая ошибка или конфликт областей | Порядок и наследование настроек, фактический DHCP ACK |

## 16. Глоссарий

| Термин | Определение |
|---|---|
| Выражение (`expression`) | Конструкция, вычисляющая значение по данным и операциям |

| `match` | Выражение, результат которого служит ключом поиска подкласса |
| `subclass` | Зарегистрированное значение ключа внутри класса |
| `option` в выражении | Полученное из DHCP-пакета значение опции |
| `option` как оператор | Настройка параметра, который сервер может отправить клиенту |
| `hardware` | Аппаратный тип и аппаратный адрес клиента в бинарном виде |
| `leased-address` | IP-адрес аренды в соответствующем контексте |
| `substring()` | Извлечение фрагмента байтов по смещению и длине |
| `concat()` | Объединение нескольких последовательностей байтов |
| `binary-to-ascii()` | Преобразование бинарных данных в текстовые числа |
| `pick-first-value()` | Выбор первого существующего непустого значения |
| `set` | Присвоение значения переменной |
| `exists` | Проверка присутствия опции |
| `on commit` | Обработчик события подтверждения аренды |
| Option 60 | Vendor Class Identifier — идентификатор типа клиента |
| Option 61 | DHCP Client Identifier — идентификатор клиента |

## Итоги — что было разобрано

- Выражения позволяют использовать содержимое DHCP-запроса при классификации, выборе опций и обработке событий.
- `substring()`, `concat()`, `binary-to-ascii()` и `pick-first-value()` решают разные задачи обработки байтов и строк.
- `hardware` включает тип оборудования; `leased-address` доступен в контексте аренды; `option` может означать полученное значение или настройку ответа — в зависимости от синтаксиса.
- `set` создает промежуточное значение, но само по себе не отправляет DHCP Option и не изменяет DNS.
- Для диагностики необходимы как проверка конфигурации, так и анализ реальных DHCP-пакетов.
