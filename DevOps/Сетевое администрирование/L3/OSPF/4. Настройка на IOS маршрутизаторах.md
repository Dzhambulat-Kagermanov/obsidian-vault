### Базовая конфигурация процесса OSPF:

Все начинается с создания процесса. Номер процесса локален для устройства (может отличаться у соседей), но Router ID должен быть уникальным во всей сети:

```Router
! Запуск процесса OSPF (номер процесса локален, например, 1)
router ospf 1

! 1. КРИТИЧЕСКИ ВАЖНО: Явное задание Router ID
! Лучше использовать IP адрес Loopback интерфейса.
! Это обеспечивает стабильность при перезагрузке физических интерфейсов.
router-id 1.1.1.1

! 2. Настройка областей (Areas) и включение интерфейсов
! Синтаксис: network <IP_сети> <wildcard-mask> area <ID_области>
! Wildcard маска — это инверсия subnet mask (0.0.0.255 вместо 255.255.255.0)

! Пример: Включаем все интерфейсы подсети 10.0.0.0/24 в Area 0
network 10.0.0.0 0.0.0.255 area 0

! Пример: Интерфейс 192.168.10.1/30 в Area 1
network 192.168.10.0 0.0.0.3 area 1

! 3. Пассивные интерфейсы (Passive Interfaces)
! Отключает отправку Hello-пакетов на интерфейсах, где нет соседей (LAN, Loopback).
! Это безопасность и экономия ресурсов.
passive-interface default
! Возвращаем активный статус только там, где есть соседи (uplink)
no passive-interface GigabitEthernet0/0
no passive-interface GigabitEthernet0/1
```

### Создание и настройка специальных зон (Stub, NSSA):

Настройка типов зон делается **на всех роутерах внутри этой области**, включая ABR. Если настройки не совпадут, соседство не поднимется (ошибка mismatch):

**Stub Area (Тупиковая зона)**. Блокирует LSA Type 5 (внешние). ABR автоматически шлет дефолтный маршрут.
```Router
router ospf 1
 ! Можно писать на любом роутере внутри Area 10:
 area 10 stub
```

**Totally Stubby** (блокировать еще и Type 3, оставив только дефолт). `no-summary` ставится только на ABR, обычные роутеры в зоне знают просто `stub`:
```Router
router ospf 1
 ! ТОЛЬКО на ABR:
 area 10 stub no-summary
```

**NSSA.** Разрешает локальную редистрибьюцию (Type 7), блокирует входящие Type 5.
```Router
router ospf 1
 ! Можно писать на любом роутере внутри Area 20:
 area 20 nssa
```

Чтобы ABR генерировал дефолтный маршрут внутрь NSSA (часто требуется):
```Router
router ospf 1
 area 20 nssa default-information-originate
```

**Totally NSSA** (нет Type 3, только дефолт + свои Type 7):
```Router
router ospf 1
 ! ТОЛЬКО на ABR:
 area 20 nssa no-summary
```

### Тонкая настройка и оптимизация:

OSPF считает стоимость как `RefBW / IntBW`. По умолчанию RefBW = 100 Mbps. Для гигабитных линков (1 Gbps) стоимость будет `100/1000 = 1`. Для 10G тоже 1. Это плохо.
```Router
router ospf 1
 ! Меняем опорную полосу пропускания на 10 Гбит (или 100 Гбит)
 auto-cost reference-bandwidth 10000
 ! Теперь 1G будет стоить 10, а 10G - 1.
 ! Внимание: нужно менять на ВСЕХ роутерах в сети!

! Или вручную на интерфейсе: 
interface GigabitEthernet0/0
 ip ospf cost 50
```

### Аутентификация:

Безопасность обязательна. Используем MD5 или SHA (в новых IOS):
```Router
! Вариант 1: На интерфейсе (MD5)
interface GigabitEthernet0/0
 ip ospf authentication message-digest
 ip ospf message-digest-key 1 md5 MySecretPassword

! Вариант 2: Глобально для области (SHA/HMAC - предпочтительнее)
router ospf 1
 area 0 authentication message-digest
! Затем на интерфейсах задаем ключи
interface GigabitEthernet0/0
 ip ospf message-digest-key 10 sha-256 MyStrongerKey
```

### Ускорение конвергенции:

По умолчанию Hello 10s, Dead 40s. Для быстрых сетей можно уменьшить. 
```Router
interface GigabitEthernet0/0
 ip ospf hello-interval 1
 ip ospf dead-interval 4
 ! Или использовать функцию fast-timers (зависит от версии IOS)
```

> Важно! Таймеры должны совпадать у соседей.

### Loop-Free Alternate Fast Reroute (LFA FRR):

Стандартный OSPF ждет падения линка (Dead timer), затем пересчитывает SPF. Это занимает секунды. LFA позволяет роутеру **заранее** вычислить резервный путь (Backup Next-Hop), который не образует петель. При падении основного линка переключение происходит за **50 мс** на уровне forwarding plane, не дожидаясь пересчета протокола. Актуально в топологиях с треугольниками или кольцами.

```Router
router ospf 1
 fast-reroute per-prefix enable all
 ! Или более тонкая настройка через tie-breakers
```

### OSPF over Demand Circuits (DCO):

Идеально для сценариев с **GRE/IPSec туннелями** или резервными каналами (LTE/4G), где трафик платный или канал нестабилен.

**Проблема.** OSPF шлет Hello-пакеты каждые 10 секунд, поддерживая линк активным. Это будит канал, тратит ресурсы и может ронять соединение при кратковременных потерях пакетов.

Флаг `DoNotAge` (DNA). Роутеры обмениваются LSDB один раз при старте, а потом подавляют периодические обновления (LSA Refresh). Линк считается "Up" даже если нет Hello-пакетов, пока физическое соединение не упадет окончательно.

```Router
interface Tunnel0
 ip ospf demand-circuit
```

> Важно! Работает только если оба соседа поддерживают эту опцию. Не работает в Broadcast сетях (только P2P).

### BFD (Bidirectional Forwarding Detection):

OSPF Dead Timer минимум 1 секунда (при агрессивных настройках), обычно 40с. Для современных сетей это медленно.

BFD — это сверхлегкий протокол (работает на UDP), который может детектировать падение линка за **миллисекунды** (интервалы 50мс/150мс). Он интегрируется с OSPF. Как только BFD видит проблему, он сразу сообщает OSPF: "Линк down!", и OSPF мгновенно рвет соседство и пересчитывает пути.

```Router
! Глобально или на интерфейсе
interface GigabitEthernet0/0
 bfd interval 50 min_rx 50 multiplier 3
 ip ospf bfd
```

### Фильтрация между областями OSPF:

Возможна только на маршрутизаторах границах области, таких как ABR и ASBR, это фильтрация **LSA 3**. Фильтрация осуществляется с помощью префикс листов (prefix list). Фильтрация **LSA 3** говорит маршрутизатору не анонсировать сети из одной области в другую, тем самым закрывая доступ к сетям, которые не должны отображаться в других областях.

### Фильтрация внутри области OSPF:

Она просто не добавляет указанный маршрут в таблицу маршрутизации, но в базе OSPF LSDB маршрут до сети будет.

### Max-Metric Router LSA (Graceful Shutdown / Maintenance):

**Проблема.** Как вывести роутер из эксплуатации без разрыва тысяч сессий? Если ты просто выключаешь интерфейс или reboot-нешь роутер, трафик резко потечет в другое место, возможно, перегрузив его.

Команда `max-metric router-lsa`. Роутер продолжает работать, но в своих LSA Type 1 объявляет все свои линки с метрикой **65535** (бесконечность).

Соседи видят, что путь через этот роутер стал самым дорогим, и плавно переносят трафик на альтернативные пути. После того как трафик ушел, можно спокойно reboot-ать роутер.

```Router
router ospf 1
 max-metric router-lsa
 
! Или с таймером (вернуть нормальную метрику через 300 сек, если что-то пошло не так):
 max-metric router-lsa on-startup 300
```

### Sham Links (Для MPLS L3VPN):

**Сценарий:** У клиента OSPF сеть разбита на две части, соединенные через MPLS облако провайдера;

**Проблема:** OSPF считает путь через MPLS (Backdoor link) как "внешний" (E1/E2), а прямой резервный линк между офисами (если он есть) как внутренний (Intra-area). Внутренний путь всегда приоритетнее внешнего. Трафик пойдет по медленному резервному каналу, игнорируя быстрый MPLS.

**Sham Link** - это виртуальный туннель между PE-роутерами провайдера, который делает маршрут через MPLS "внутри-областным" (Intra-area) с точки зрения клиентского OSPF.

Настраивается на PE роутерах в адресном пространстве клиента.

### NSF (Non-Stop Forwarding) и Graceful Restart:

При перезагрузке процесса OSPF (или всего роутера, если есть dual control plane), роутер сообщает соседям: "Я перезагружаюсь, но мой forwarding plane (железо) работает. Не удаляйте мои маршруты, подождите меня".

```Router
router ospf 1
 nsf cisco helper disable ! (или enable в зависимости от роли)
 graceful-restart
```

> Важно! Соседи тоже должны поддерживать эту функцию (быть "helpers"), иначе они сбросят соседство при пропаже Hello.

### Лимиты и защита (Control Plane Policing):

Чтобы OSPF не "убил" процессор роутера при атаке или флэппинге:

* **Max-LSA:** Ограничивает количество LSA, которые роутер готов принять. Если лимит превышен, роутер переходит в режим "ignore" и рвет соседства, чтобы спасти CPU:
```Router
router ospf 1
 max-lsa 12000 80 ! Предупредить при 80%, вырубиться при 12000
```

* **SPF Throttling:** Настройка задержек между пересчетами SPF:
```Router
router ospf 1
 timers throttle spf 100 500 5000
 ! Начальная задержка 100мс, между повторными 500мс, макс 5000мс.
 ! Защищает от циклических пересчетов при нестабильном линке.
```

### Команды для отладки:

* `show ip ospf neighbor` — Вывод всех соседей;
* `show ip ospf interface brief` — Вывод краткой сводки сетей участвующих в процессе OSPF;
* `show ip ospf database` — Выводит таблицу топологии OSPF (LSDB — Link State Database);
* `show ip route ospf` — Вывод маршрутов (O, O IA, O E1/E2, ...);
