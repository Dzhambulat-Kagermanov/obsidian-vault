### Фундаментальное понятие:

**Цепочка фильтрации (Filter Chain)** — это упорядоченный список правил (набор критериев и действий), через которые пропускается каждый сетевой пакет, проходящий через определенную точку в ядре операционной системы.

- **Суть:** Это не просто список, а _линейный алгоритм_ проверки. Пакет сравнивается с правилами строго по очереди, начиная с первого.
- **Действие (Target/Verdict):** Когда пакет совпадает с критериями правила, к нему применяется действие, и движение по цепочке (как правило) прекращается.
- **Политика по умолчанию (Default Policy):** Если пакет не совпал ни с одним правилом, применяется действие по умолчанию (обычно ACCEPT или DROP).

### Архитектурный контекст:

В контексте Linux (а это 99% сетевых устройств, от роутеров до серверов) цепочки — это часть подсистемы **Netfilter**.

Исторически использовался фреймворк `iptables`, где были предопределенные таблицы и цепочки. Сегодня ему на смену пришел **nftables**, который унифицирует все. Мы разберем современный подход `nftables`, но с проекцией на классические понятия `iptables`, так как они все еще встречаются повсеместно и хорошо описывают логику.

**Важнейшая концепция — хуки (netfilter hooks):**  
Ядро Linux предоставляет 5 ключевых точек (ловушек) в стеке обработки пакетов, к которым можно "привязать" цепочки.

### Точки входа в цепочки и путь пакета:

Это основа основ. Понимание пути пакета критично для написания правил.

**Пять ключевых хуков (точек фильтрации):**

1. **`Prerouting` (Предварительная маршрутизация)**
    - **Где:** Точка входа пакета в сетевой стек, сразу после получения с сетевой карты (NIC).
    - **Тип трафика:** Весь входящий трафик (и для локальных процессов, и для транзита).
    - **Для чего:** Изменение заголовков пакета (NAT: DNAT — destination NAT, проброс портов), ранняя фильтрация DDoS.
2. **`Input` (Входящий)**
    - **Где:** После того, как решение о маршрутизации определило, что пакет предназначен локальному процессу.
    - **Тип трафика:** Только пакеты, адресованные этой машине.
    - **Для чего:** Основная точка защиты сервера. Фильтрация того, что может достичь ваших приложений (SSH, веб-сервер).
3. **`Forward` (Транзитный/Проброс)**
    - **Где:** После того, как решение о маршрутизации определило, что пакет нужно отправить на другой хост.
    - **Тип трафика:** Пакеты, которые проходят через эту машину насквозь.
    - **Для чего:** Ключевая точка для маршрутизаторов, файрволов, NAT-шлюзов. Контроль трафика между сегментами сети.
4. **`Output` (Исходящий)**
    - **Где:** Точка, где пакет, сгенерированный локальным процессом, попадает в сетевой стек.
    - **Тип трафика:** Только пакеты, которые создала эта машина.
    - **Для чего:** Контроль исходящих соединений, ограничение доступа приложений, изменение исходящего трафика.
5. **`Postrouting` (Пост-маршрутизация)**
    - **Где:** Самая последняя точка перед тем, как пакет "уйдет на провод" и будет отправлен драйвером сетевой карты.
    - **Тип трафика:** Любой трафик, покидающий хост (сгенерированный локально или транзитный).
    - **Для чего:** Изменение заголовков пакета (NAT: SNAT — source NAT, маскарадинг). Правила здесь гарантируют, что пакет уйдет с правильным IP-адресом исходящего интерфейса.

### Правила внутри цепочки:

Правило состоит из двух частей: **Критерии совпадения (Matches)** и **Действие (Action/Verdict)**.

#### Критерии совпадения (Matches):

1. **Мета-информация (Meta):**
    - `meta iif eth0` (входящий интерфейс)
    - `meta oif eth1` (исходящий интерфейс)
    - `meta skuid 1000, meta skgid 1000` (ID пользователя/группы процесса-отправителя)
    - `meta mark 0x10` (маркер пакета, установленный ранее)
    - `meta time "2024-01-01", meta hour "09:00-18:00"` (время)
    - `meta cpu 0-3` (привязка к ядрам CPU)
2. **Данные полезной нагрузки (Payload):** Сырые данные из заголовков пакета.
    - `ip saddr 192.168.1.0/24` (IP-адрес источника)
    - `tcp dport {22, 80, 443}` (TCP-порт назначения)
    - `icmp type echo-request` (Тип ICMP)
    - `tcp flags syn / fin,syn,rst,ack` (TCP-флаги)
    - `ct state new` (состояние соединения, об этом ниже)
    - `limit rate 5/second` (ограничение скорости)
3. **Динамическое отслеживание (Stateful Firewall, conntrack):** Самый мощный механизм. Ядро ведет таблицу всех соединений (`/proc/net/nf_conntrack`).
    - **`ct state new`**: Пакет создает новое соединение (первый SYN).
    - **`ct state established`**: Пакет принадлежит уже существующему соединению.
    - **`ct state related`**: Пакет связан с существующим соединением (например, данные FTP или ICMP "Port Unreachable").
    - **`ct state invalid`**: Пакет не соответствует ни одному известному состоянию (обычно DROP).

#### Действия (Actions / Verdicts):

1. **Терминальные (завершают обход цепочки):**
    - **`accept`**: Немедленно разрешить пакет. Прекратить обход текущей цепочки, пакет идет дальше по пути.
    - **`drop`**: Немедленно удалить пакет. Никакого ответа отправителю.
    - **`reject`**: Удалить пакет, но отправить отправителю ICMP-уведомление об ошибке (например, `icmp port-unreachable`). Вежливый `drop`.
    - **`queue`**: Отправить пакет в пространство пользователя (userspace) для обработки программой (через библиотеку nfnetlink_queue), например, сложным антивирусным сканером.

2. **Нетерминальные (изменяют пакет и продолжают):**
    - **`dnat to 10.0.0.1:8080`**: Изменить destination NAT (работает только в `nat` цепочках на хуке `prerouting` или `output`).
    - **`snat to 203.0.113.1`**: Изменить source NAT (работает только в `nat` цепочках на хуке `postrouting` или `input`).
    - **`masquerade`**: Специальная форма SNAT, где IP-адрес источника автоматически берется от исходящего интерфейса.
    - **`mark set 0x10`**: Поставить метку на пакет для последующей обработки в другой цепочке или для политик маршрутизации (`ip rule`).
    - **`log prefix "MyPrefix: "`**: Записать информацию о пакете в системный журнал.
    - **`counter`**: Увеличить счетчик пакетов и байт для правила.

3. **Переходы:**
- **`jump my_own_chain`**: Безусловный переход в другую пользовательскую цепочку. Когда обход `my_own_chain` завершится (accept или конец без политики), мы вернемся в точку сразу после `jump`.
- **`goto my_own_chain`**: Переход. Когда обход `my_own_chain` завершится, мы **не** возвращаемся, а применяем её политику по умолчанию. Используется для "подпрограмм", которые должны принять окончательное решение.

### Политика по умолчанию (Base Chain Policy):

У каждой _базовой цепочки_ (той, что привязана к хуку) есть политика по умолчанию. Она срабатывает, если пакет дошел до конца цепочки и ни одно правило не вынесло терминальный вердикт.

Обычные значения: `accept` (разрешающая модель) или `drop` (запрещающая модель).

**Золотое правило безопасности:** Политика по умолчанию — всегда `drop`. Все что не разрешено - запрещено. Это "whitelist" подход.

### Цепочки и качество обслуживания (QoS) — немного о TC:

Хотя фильтрация обычно про Netfilter, "цепочки" существуют и в подсистеме Traffic Control (`tc`). Там пакеты попадают в цепочки дисциплин (qdisc) и классов, где над ними выполняются действия: задержка, переупорядочивание, шейпинг, дроп. Netfilter-метки (marks) часто служат мостом: сначала в Netfilter пакету ставится маркер, а затем `tc` на основе этого маркера отправляет его в нужную очередь.
