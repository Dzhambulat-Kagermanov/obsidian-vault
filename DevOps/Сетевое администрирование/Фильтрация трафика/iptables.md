### Фундаментальное понятие:

Iptables — это не демон, а утилита командной строки для управления встроенным в ядро Linux файрволом **Netfilter**. Правила применяются мгновенно, но не переживают перезагрузку (если не сохранить их отдельно).

- **Таблицы (Tables):** Группируют правила по типу обработки.
    - `filter` — Базовая фильтрация трафика (используется в 90% случаев).
    - `nat` — Трансляция сетевых адресов (роутинг, проброс портов).
    - `mangle` — Модификация заголовков пакетов (QoS, TTL).
    - `raw` — Обход отслеживания соединений (conntrack).
- **Цепочки (Chains):** Точки входа в таблицу (где ловится пакет).
    - `PREROUTING` — Точка входа пакета в сетевой стек, сразу после получения с сетевой карты (NIC).
    - `INPUT` — Трафик, предназначенный самому хосту.
    - `OUTPUT` — Трафик, исходящий с хоста.
    - `FORWARD` — Транзитный трафик (хост работает как роутер).
    - `POSTROUTING` — Самая последняя точка перед тем, как пакет "уйдет на провод" и будет отправлен драйвером сетевой карты.
- **Правила (Rules):** Критерий выборки + Действие (Target).
    - Если пакет совпал с условием, к нему применяется действие, и цепочка прерывается (кроме случаев с non-terminating targets).

### Механизм принятия решения (Netfilter Flow)

#### Путь пакета:

Пакет проходит путь в строгой последовательности (упрощенно):

![[1576325460345.jpg]]

Пакет проходит путь в строгой последовательности (упрощенно):

1. Попадает в сетевой интерфейс.
2. **raw.PREROUTING** (реже используем).
3. Отслеживание соединений (Conntrack).
4. **mangle.PREROUTING**.
5. **nat.PREROUTING** (DNAT — подмена адреса назначения).
6. Принятие решения о маршрутизации:
    - _Пакет локальному процессу?_ → **mangle.INPUT** → **filter.INPUT** → Процесс.
    - _Пакет транзитный?_ → **mangle.FORWARD** → **filter.FORWARD** → **mangle.POSTROUTING** → **nat.POSTROUTING** (SNAT/Masquerade).
7. От локального процесса ответ идет через: **mangle.OUTPUT** → **nat.OUTPUT** → **filter.OUTPUT** → **mangle.POSTROUTING** → **nat.POSTROUTING**.

#### Действия (Targets)

- **ACCEPT / DROP** — Пропустить или уничтожить (тихо). DROP лучше, чем REJECT (не даем обратную связь сканерам).
- **REJECT** — Отбросить, но отправить ICMP-ответ (обычно `icmp-port-unreachable`). Выдает присутствие хоста.
- **LOG** — Записать пакет в syslog и пойти дальше по цепочке.
- **SNAT / DNAT / MASQUERADE** — Подмена источника/назначения.


### Основные команды:

#### Просмотр правил (Инспекция):

Основная команда: `iptables -L`

- **`-L [CHAIN]`** — List. Вывести список правил. Если цепочку не указать, показывает всю таблицу.  
- **`-v`** — Verbose. Показывает счетчики пакетов и байт, интерфейс, опции.
- **`-n`** — Numeric. Не резолвить IP в DNS и порты в имена сервисов. Без этого команда может зависнуть на DNS-запросах.
- **`--line-numbers`** — Показывает номера строк (критично для удаления и вставки).

```bash
# Самый полезный вариант: числовой вывод с номерами строк и счетчиками
iptables -L INPUT -v -n --line-numbers

# Посмотреть только цепочку SSH_BLOCK (если создавали кастомную)
iptables -L SSH_BLOCK -v -n

# Посмотреть таблицу NAT (по умолчанию смотрим filter)
iptables -t nat -L -v -n --line-numbers
```

#### Удаление правил:

##### Удаление по номеру строки:

Самый надежный способ.
1. Смотрим номера: `iptables -L INPUT --line-numbers`
2. Удаляем конкретную строку: `iptables -D INPUT <номер>`

```bash
# Видим, что правило номер 3 лишнее
iptables -D INPUT 3
```

_Важно:_ После удаления нумерация сдвигается. Если нужно удалить правила 3 и 5, удаляйте сначала 5, потом 3, либо после удаления 3 заново посмотрите список.

##### Удаление по совпадению:

Полное повторение синтаксиса правила, только вместо `-A` (append) пишем `-D` (delete).

```bash
iptables -D INPUT -p tcp --dport 8080 -j DROP
```

_Подводный камень:_ Если таких правил несколько, удалится только первое. Лучше использовать номера строк.

#### Очистка и сброс:

Очистка правил (Flush)
- **`-F [CHAIN]`** — Flush. Удаляет все правила в цепочке. Если цепочка не указана — во всех.
- **`-t nat -F`** — Очистка таблицы nat.

```bash
# Очистить таблицу filter (цепочки INPUT, FORWARD, OUTPUT)
iptables -F

# Очистить только цепочку INPUT
iptables -F INPUT
```

_Важно:_ `-F` не сбрасывает политики (`-P`). Если у вас стояла политика `DROP`, после очистки всех правил машина станет недоступна по сети.

### Best Practices (Как писать безопасные правила)

#### Политика по умолчанию — DROP

Золотой стандарт: «Запрещено всё, что не разрешено явно».

```bash
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT # Исходящий трафик обычно разрешаем
```

#### Разрешать только необходимое (Whitelisting)

Не запрещайте порты злоумышленников, разрешайте порты своих сервисов.

```bash
# Разрешаем loopback (критично для многих сервисов типа БД)
iptables -A INPUT -i lo -j ACCEPT

# Разрешаем уже установленные соединения (Stateful firewall)
iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# Разрешаем SSH (желательно с rate limiting)
iptables -A INPUT -p tcp --dport 22 -m conntrack --ctstate NEW -j ACCEPT

# Разрешаем HTTP/HTTPS
iptables -A INPUT -p tcp -m multiport --dports 80,443 -m conntrack --ctstate NEW -j ACCEPT
```

#### Stateful Inspection (Отслеживание состояний)

Самая важная строка в iptables:  
`-m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT`

- **ESTABLISHED:** Пакеты, принадлежащие известному соединению (ответы на наши запросы, ответы клиентам).
- **RELATED:** Новое соединение, логически связанное с существующим (например, FTP-данные). Это позволяет не открывать динамические порты пачками.

#### Атомарность и сохранение

Никогда не применяйте правила из командной строки на боевом сервере по одному. Используйте скрипты и файлы правил.
1. Создайте файл `/etc/iptables/rules.v4`.
2. Применяйте атомарно: `iptables-restore < /etc/iptables/rules.v4`.
3. Для теста используйте утилиту `iptables-apply` (она применит правила и спросит подтверждение; если не ответить за 10 сек — откатит).

### Подводные камни:

#### Ложное чувство безопасности с DROP (и потеря SSH)

**Проблема:** Вы выполнили `iptables -P INPUT DROP`, и у вас сразу отвалился SSH.  

**Почему:** Политика действует на пакеты, не попавшие ни под одно правило. Если разрешающего правила для порта 22 еще не было — вы заперты.  

**Решение:**
- Использовать `iptables-apply`.
- В скриптах всегда сначала идут разрешающие правила (особенно `ESTABLISHED` и SSH), и только потом `-P INPUT DROP`.
- Иметь консольный доступ (KVM/IPMI) как запасной вариант.

#### Цепочка не останавливается после LOG:

**Проблема:** Вы добавили правило логирования перед DROP, но трафик продолжает идти.

```bash
# Неправильно
iptables -A INPUT -j LOG --log-prefix "DROP: " # Пакет залогирован, но цель LOG — non-terminating
# Пакет выйдет из цепочки и применится политика по умолчанию (если она ACCEPT, трафик пройдет!)
```

**Решение:** После лога должно идти правило с terminating target (DROP/REJECT):

```bash
iptables -A INPUT -j LOG --log-prefix "INPUT DROP: "
iptables -A INPUT -j DROP
```

Либо создать кастомную цепочку и прыгать в неё: `-j LOG_DROP`.

#### Петля блокировок локальных сервисов:

**Проблема:** База данных не стартует или не видит друг друга на localhost при жестких правилах.  

**Причина:** Забыли разрешить интерфейс loopback (`lo`).

**Решение:**

```bash
iptables -A INPUT -i lo -j ACCEPT
iptables -A OUTPUT -o lo -j ACCEPT
```

Иначе все взаимодействие через `127.0.0.1` будет заблокировано.

#### Неправильное понимание NEW:

**Проблема:** Правило `-p tcp --dport 22 -j ACCEPT` пропускает ВСЕ пакеты на порт 22, даже мусорные и без флага SYN.

**Решение:** Всегда добавлять проверку состояния для входящих подключений:  
`-m conntrack --ctstate NEW,ESTABLISHED -j ACCEPT`. Это гарантирует, что через порт пройдет только инициация соединения (SYN), а не подделанный ACK.

#### Masquerade против SNAT:

- **MASQUERADE** — Динамический подбор адреса. Медленнее (ищет адрес интерфейса для каждого пакета), но выживает при смене IP на интерфейсе (DHCP).
- **SNAT** — Статическая подмена на конкретный IP. Быстрее, но если IP интерфейса сменился, трафик ломается.  
    _Камень:_ Если использовать SNAT на роутере с динамическим внешним IP, после смены адреса провайдером клиенты останутся без интернета.

#### Порядок правил в цепочке:

Правила обрабатываются сверху вниз. Если первым стоит разрешение порта 80 для всех, а ниже — запрет для конкретного IP, запрета не произойдет. Ставьте специфичные (блокирующие) правила выше общих (разрешающих).
