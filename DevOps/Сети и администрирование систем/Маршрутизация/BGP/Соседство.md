
**Соседство между маршрутизаторами** - это установление доверенности с обеих сторон, то есть для создания соседства оба маршрутизатора должны доверять друг другу. 

**Соседство** это лишь обмен маршрутами между маршрутизаторами. Для установления соседства необходимы следующие условия: 
* Сетевая связанность;
* Взаимная конфигурация доверия;
* Совпадение параметров (например `ebgp-multihop`).

Соседство устанавливается командой:
```Router
neighbor <IP> remote-as <ASN>
```

После ввода команды отрабатывают следующие процессы:
1. **Установка TCP-сессии:** Ваш роутер стучится к соседу (или ждет, пока постучат они) на порт 179;
2. **Обмен таблицами (Full Table Exchange):** Соседи обмениваются **полными списками** сетей, которые они анонсируют:
    - Сосед говорит: «Я знаю пути к сетям A, B, C».
    - Вы говорите: «А я знаю пути к сетям X, Y, Z».
3. **Заполнение таблицы BGP (BGP RIB):** Эти полученные маршруты сохраняются в специальную таблицу BGP.

> **Важный момент:** В этот момент трафик **еще не идет** через соседа! Маршруты просто лежат в таблице BGP как «кандидаты».

Трафик пойдет через этого соседа только после того, как произойдет два дополнительных шага, которые выполняются автоматически, но зависят от условий:

1. **Выбор лучшего пути (Best Path Selection):** Алгоритм BGP просматривает все полученные маршруты (возможно, вы узнали путь к сети `8.8.8.0/24` от этого соседа и еще от трех других). Он выбирает **один лучший** путь berdasarkan правилам (самый короткий AS_PATH, высокий LOCAL_PREF и т.д.):
    - Если путь через этого конкретного соседа оказался **лучшим**, он переходит в следующий этап.
    - Если путь через другого соседа лучше, то трафик пойдет через другого, а этот сосед будет служить резервом.
2. **Установка в таблицу маршрутизации ядра (Installation to Global RIB):** Только **лучший** маршрут из таблицы BGP копируется в основную таблицу маршрутизации Linux (`ip route show` или `show ip route`). И вот только когда запись появляется в таблице ядра (`ip route`), операционная система начинает реально отправлять пакеты данных на IP-адрес этого соседа (Next Hop).

### Анонсирование сетей соседям:

По умолчанию, даже при установленном соседстве, вы молчите о своих сетях. Сосед видит вас как «пустое место» — он знает путь к вам, но не знает, какие сети за вами находятся. Чтобы сосед узнал о ваших сетях, вы должны явно сказать BGP-процессу: «Вот эти сети мои, передай их всем моим соседям (или конкретному соседу)».

#### Анонсирование сетей через network:

Это прописывание всех сетей для каждого соседа вручную через команду network. Такой способ является контролируемым и рекомендуемым. Сеть должна уже существовать в таблице маршрутизации вашего роутера. Пример конфигурации:

```Router
router bgp 65001
  neighbor 192.168.1.2 remote-as 65002
  
  # Говорим: "Если у меня есть сеть 10.10.10.0/24, объяви её соседу"
  network 10.10.10.0/24
  
  # Можно объявить и свой loopback
  network 1.1.1.1/32
```


#### Анонсирование сетей через перераспределение (redistribute):

Вы говорите: «Возьми ВСЕ маршруты, которые я знаю из другого источника (например, из подключенных интерфейсов или OSPF), и залей их в BGP».

```Router
router bgp 65001
  neighbor 192.168.1.2 remote-as 65002
  
  # Опасно! Может слить в интернет лишние служебные сети
  redistribute connected
  
  # Или взять маршруты из OSPF
  redistribute ospf
```

#### Анонсирование конкретных сетей для соседа:

```Router
router bgp 65000
  ! Сосед А (источник)
  neighbor 1.1.1.1 remote-as 65001
  ! Фильтруем вход: пропускаем только то, что хотим видеть у себя
  neighbor 1.1.1.1 route-map <ROUTER_MAP_TEMPLATE_FROM_A> in

  ! Сосед Б (получатель)
  neighbor 2.2.2.2 remote-as 65002
  ! Фильтруем выход: решаем, что именно этот сосед увидит
  ! Даже если в таблице BGP 1 млн маршрутов, Сосед Б увидит только то, что разрешил route-map TO_B
  neighbor 2.2.2.2 route-map <ROUTER_MAP_TEMPLATE_TO_B> out

  ! Сосед В (другой получатель, которому мы НЕ хотим отдавать маршруты от А)
  neighbor 3.3.3.3 remote-as 65003
  ! Тут может стоять пустой route-map или такой, который разрешает только наши локальные сети
  neighbor 3.3.3.3 route-map <ROUTER_MAP_TEMPLATE_ONLY_LOCAL> out
```

### Дополнительные настройки соседства:

#### Next-Hop в iBGP:

Принудительно меняет атрибут **Next-Hop** (Следующий прыжок) на IP-адрес вашего локального интерфейса (обычно тот, с которого идет BGP-сессия) при отправке обновлений этому соседу.

```Router
router bgp <ASN>
	address-family ipv4 unicast
		neighbor 10.0.0.2 next-hop-self
```

Все маршруты, уходящие к `10.0.0.2`, будут иметь Next-Hop = ваш IP (например, `1.1.1.1`).

**Зачем нужно:**

- **Основной кейс (iBGP):** Когда вы передаете внешние маршруты (полученные от eBGP соседа) внутреннему соседу (iBGP). По умолчанию BGP не меняет Next-Hop внутри одной AS. Внутренний роутер может не знать, как добраться до внешнего IP провайдера. `next-hop-self` говорит ему: «Иди ко мне, я уже знаю путь».
- **Вторичный кейс (eBGP с несколькими хопами):** Иногда полезно в сложных топологиях, чтобы скрыть реальную структуру сети за собой.

#### Source IP:

Указывает роутеру, какой именно локальный IP-адрес (или интерфейс) использовать в качестве **источника** (Source IP) для TCP-пакетов BGP-сессии с этим соседом.

```Router
interface lo1
	ip address 192.168.255.1

router bgp <ASN>
	neighbor 192.168.255.2 update-source lo1
```

**Зачем нужно:**

- **Стабильность сессий:** По умолчанию роутер использует IP того интерфейса, через который физически идет пакет к соседу. Если этот интерфейс упадет, сессия разорвется, даже если есть другой путь.
- **Использование Loopback:** Вы хотите, чтобы сессия строилась на стабильном IP адресе Loopback (`1.1.1.1`), который никогда не падает. Сосед тоже должен стучаться на этот IP.
- **Требование для многопутевости:** Если между роутерами несколько каналов (ECMP), сессия должна быть привязана к одному логическому адресу, а не скакать между физическими IP.

> **Важно!** У соседа должна быть аналогичная настройка `update-source`, например `neighbor 192.168.255.1 update-source lo1`, чтобы пакеты возвращались обратно по нужному интерфейсу для установления соседства.

#### Маршрут по умолчанию:

Заставляет ваш роутер генерировать и анонсировать маршрут по умолчанию (`0.0.0.0/0`) вашим BGP-соседям.

**Зачем нужно:**

- **Для клиентов:** Чтобы вашим клиентам не нужно было качать полную таблицу интернета (миллион записей). Вы говорите им: «Всё, чего нет в вашей таблице, шлите мне».
- **Экономия ресурсов:** Клиент хранит 1 запись вместо 1 млн.

Вы слете `0.0.0.0/0` соседу, даже если у вас самих нет интернета (маршрута 0.0.0.0 в таблице). Опасно, может создать черную дыру.

```Router
router bgp 65000
  neighbor 10.0.0.5 remote-as 65002
  ! Всегда слать дефолт этому соседу
  neighbor 10.0.0.5 default-information originate
```
