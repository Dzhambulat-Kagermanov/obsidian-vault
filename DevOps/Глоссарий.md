
> [!INFO] О файле
> Центральный файл с определениями терминов, используемых в базе знаний. 
> Ссылки на термины из других тем оформляются через якоря: [[Глоссарий#термин| термин]]

### Пакет (package)
Архив с программой, её конфигурационными файлами, документацией и метаданными (версия, зависимости, описание). Аналогия: "коробка с товаром" в магазине.

### .deb файл
Формат пакета Debian. Это `ar`-архив, содержащий метаданные (`control.tar.gz`), файлы программы (`data.tar.gz`) и скрипты установки. Аналогия: `.zip` или `.tar.gz`, но со специальной структурой.

### Архитектура (architecture)
Тип процессора, для которого собран пакет: `amd64` (x86_64), `arm64`, `i386`. Аналогия: "версия программы для Windows/Mac/Linux", но для разных процессоров.

### Зависимость (dependency)
Другой пакет, который необходим для работы текущего. Аналогия: "для установки игры нужен DirectX" — DirectX это зависимость.

### Репозиторий (repository)
Централизованное хранилище пакетов с метаданными и подписями. Аналогия: "App Store, но для Linux-программ" — сервер, откуда система скачивает пакеты.

### GPG-ключ
Криптографический ключ, используемый для проверки подлинности пакетов и репозиториев. Гарантирует, что пакет не был подменён. Аналогия: "печать на конверте", подтверждающая отправителя.

### Скрипты сопровождения (maintainer scripts)
Bash-скрипты внутри пакета, выполняющиеся до/после установки или удаления: `preinst`, `postinst`, `prerm`, `postrm`. Аналогия: "инструкция по сборке мебели", которая автоматически выполняется.

### Статус пакета
Состояние пакета в системе: установлен, удалён, настроен, сломан и т.д. Отражается в базе данных `/var/lib/dpkg/status`.

### Inode
Структура данных в файловой системе, хранящая метаданные файла (права, владельца, размер, указатели на блоки данных), но не его имя. Каждый файл имеет уникальный inode в пределах файловой системы.

### Файловый дескриптор (FD)
Целое число, используемое ядром для идентификации открытого файла или потока ввода-вывода (stdin=0, stdout=1, stderr=2).

### sources.list
Конфигурационный файл `/etc/apt/sources.list`, содержащий список репозиториев, откуда apt скачивает пакеты. Каждая строка описывает один репозиторий.

### sources.list.d
Директория `/etc/apt/sources.list.d/` для дополнительных файлов репозиториев. Позволяет добавлять репозитории отдельными файлами, не трогая основной `sources.list`.

### Release-файл (Release file)
Файл `Release` (или `InRelease`) в корне репозитория, содержащий метаданные: список архитектур, компонентов, контрольные суммы и GPG-подпись файлов `Packages`.

### Packages-файл
Файл `Packages` (часто сжатый как `Packages.gz` или `Packages.xz`), содержащий метаданные всех пакетов в компоненте репозитория: имена, версии, зависимости, описания.

### Компонент репозитория
Часть репозитория, группирующая пакеты по лицензии и поддержке: `main` (официальная поддержка, свободное ПО), `restricted` (несвободное ПО с поддержкой), `universe` (сообщество), `multiverse` (несвободное ПО сообщества).

### Дистрибутив (в контексте APT)
Кодовое имя версии ОС (например, `focal`, `jammy`, `bookworm`) или категория обновлений (`updates`, `security`, `backports`). Используется в URL репозитория.

### Зеркало (mirror)
Копия репозитория, расположенная географически ближе к пользователям для ускорения загрузки. Синхронизируется с основным репозиторием.

### Keyring (связка ключей)
Файл или директория, содержащая доверенные GPG-ключи. В APT это `/etc/apt/trusted.gpg` и `/etc/apt/trusted.gpg.d/`.

### PPA (Personal Package Archive)
Публичный репозиторий на Launchpad, где разработчики публикуют пакеты для Ubuntu. Позволяет устанавливать свежее ПО, чем в официальных репозиториях.

### apt-transport-https
Пакет, добавляющий поддержку HTTPS-репозиториев в apt. В современных версиях apt (1.2+) встроен по умолчанию.

### Подпись репозитория (signed-by)
GPG-подпись Release-файла, гарантирующая его подлинность. Опция `signed-by` в sources.list указывает конкретный ключ для проверки.

### Apt Pinning
Механизм управления приоритетами версий пакетов в APT, позволяющий фиксировать конкретные версии или выбирать пакеты из определённых репозиториев, игнорируя стандартные правила обновления.

### Pin-Priority
Числовое значение (от -1 до 1000+), определяющее поведение APT при установке или обновлении пакета. Значение диктует, будет ли пакет проигнорирован, установлен или принудительно обновлён/понижен.

### Unattended Upgrades
Механизм автоматической установки обновлений (обычно только безопасности) в Debian/Ubuntu без вмешательства пользователя. Настраивается через одноимённый пакет и работает как фоновый systemd-сервис или cron-задача.

### Origin-Pattern
Шаблон в конфигурации unattended-upgrades, определяющий, из каких репозиториев разрешено автоматическое обновление. Использует метаданные Release-файлов, например: `o=Ubuntu,a=jammy-security` (origin=Ubuntu, archive=jammy-security).

### Blacklist (Blocklist) пакетов
Список пакетов, которые принудительно исключаются из автоматического обновления, даже если они попадают под разрешённые origin-паттерны. Используется для критичных сервисов, требующих ручного контроля или тестирования перед обновлением.

### RPM (Red Hat Package Manager)
Низкоуровневый формат пакетов и менеджер пакетов, используемый в дистрибутивах семейства Red Hat (RHEL, CentOS, Rocky, Alma, Fedora). Аналог [[Глоссарий#.deb файл| .deb файла]] и `dpkg` в мире Debian.

### DNF (Dandified YUM)
Высокоуровневый менеджер пакетов, пришедший на смену YUM в RHEL 8 и современных Fedora/Rocky/AlmaLinux. Использует библиотеку `libsolv` для быстрого и точного разрешения зависимостей. Аналог `apt`.

### Модули DNF (Modularity)
Система в DNF, позволяющая устанавливать разные версии (streams) одного и того же программного обеспечения и их профили (наборы пакетов) из одного репозитория. Например, установка PostgreSQL 13 или 15 через `dnf module`.

### Репозиторий DNF
Конфигурационный файл с расширением `.repo` в директории `/etc/yum.repos.d/`, описывающий источник RPM-пакетов, его GPG-ключи и правила включения/отключения.

### YUM (Yellowdog Updater, Modified)
Устаревший, но всё ещё широко встречающийся высокоуровневый менеджер пакетов в RHEL, CentOS 7 и более ранних версиях. Предшественник DNF, написанный на Python 2 и использующий SQLite для хранения метаданных.

### YUM Cache
Локальный кэш метаданных репозиториев и загруженных RPM-пакетов, хранящийся в `/var/cache/yum`. Используется для ускорения операций и возможности работы в оффлайн-режиме.

### YUM Plugin
Расширение для менеджера пакетов YUM, добавляющее дополнительную функциональность. Примеры: `versionlock` (фиксация версий), `changelog` (просмотр истории изменений), `copr` (поддержка сторонних репозиториев).

### RPM Database
База данных установленных пакетов, расположенная в `/var/lib/rpm`. Хранит метаданные о всех установленных RPM-пакетах, их файлах, зависимостях и скриптах. В современных версиях (RHEL 9+) использует формат SQLite (ndb), в старых — Berkeley DB (bdb).

### Spec-файл (Spec file)
Текстовый файл с расширением `.spec`, содержащий инструкции по сборке RPM-пакета из исходного кода. Включает метаданные (имя, версия), список зависимостей, команды сборки и скрипты сопровождения (%pre, %post).

### RPM Payload
Архив (обычно cpio), содержащий непосредственно файлы программы, которые будут распакованы в файловую систему при установке пакета.

### Верификация RPM (RPM Verify)
Процесс сравнения установленных файлов пакета с метаданными в RPM Database (размер, контрольная сумма MD5, права доступа, владелец). Используется для обнаружения несанкционированных изменений или повреждений файлов.

### Stream (Поток)
Конкретная мажорная версия программного обеспечения в рамках модуля. Например, в модуле `postgresql` могут быть доступны стримы `10`, `13` и `15`. Только один стрим может быть активен (enabled) одновременно.

### Profile (Профиль)
Предопределенный набор пакетов внутри stream, предназначенный для определенной роли или сценария использования. Например, профили `client` (только клиентские утилиты), `server` (сервер и зависимости) или `development` (библиотеки для разработки).

### AppStream (Application Stream)
Специальный репозиторий в RHEL 8 и совместимых дистрибутивах (Rocky, Alma), содержащий модульные приложения. Позволяет обновлять пользовательские приложения (Node.js, PostgreSQL, Nginx) быстрее и независимее от цикла выпуска базовой операционной системы (BaseOS).

### Default Stream
Стрим модуля, который включен по умолчанию, если пользователь явно не указал другой. Обычно это наиболее стабильная и протестированная вендором версия на момент выпуска дистрибутива.

### Patch Management (Управление патчами)
Процесс систематического выявления, тестирования, установки и верификации обновлений программного обеспечения (патчей) для устранения уязвимостей, исправления ошибок и улучшения функциональности. Аналогия: "регулярное техническое обслуживание и замена изношенных деталей в автомобиле".

### dnf-automatic
Служба и таймер в systemd, аналогичные unattended-upgrades в Debian/Ubuntu. Автоматизирует проверку, загрузку и установку обновлений по расписанию без вмешательства администратора.

### Live Kernel Patching (Живое обновление ядра)
Технология, позволяющая применять критические исправления безопасности к работающему ядру Linux без необходимости перезагрузки сервера. Примеры: Kpatch (от Red Hat), TuxCare (KernelCare). Аналогия: "замена колеса у движущегося автомобиля".

### CVE (Common Vulnerabilities and Exposures)
Общедоступный каталог известных уязвимостей информационной безопасности. Каждой уязвимости присваивается уникальный идентификатор (например, CVE-2023-12345), который используется системами управления патчами для сопоставления установленных версий ПО с известными угрозами.

### /etc/passwd
Текстовый файл, содержащий базовую информацию о всех пользователях системы (имя, UID, GID, комментарий GECOS, домашняя директория, оболочка). Исторически содержал пароли, но сейчас хранит только символ-заглушку "x".

### /etc/shadow
Защищенный текстовый файл, доступный для чтения только пользователю root. Хранит хэши паролей пользователей и параметры политики паролей (дата последнего изменения, минимальный и максимальный срок действия, период предупреждения, срок неактивности).

### /etc/group
Текстовый файл, содержащий информацию о группах системы: имя группы, символ-заглушка пароля группы, GID и список пользователей, входящих в эту группу в качестве дополнительных участников.

### /etc/gshadow
Защищенный файл, хранящий хэши паролей групп (если группа защищена паролем) и список администраторов группы, которые могут добавлять или удалять участников.

### /etc/login.defs
Глобальный конфигурационный файл, задающий параметры по умолчанию для утилит управления пользователями (useradd, usermod) и парольной политики (например, PASS_MAX_DAYS, UID_MIN, CREATE_HOME).

### UID (User Identifier)
Уникальный числовой идентификатор пользователя в системе. UID 0 зарезервирован для суперпользователя (root), 1-999 обычно для системных сервисов, 1000+ для обычных пользователей.

### GID (Group Identifier)
Уникальный числовой идентификатор группы в системе, используемый для управления правами доступа к файлам и ресурсам на уровне групп.
  
### Домашняя директория (Home Directory)
Персональная директория пользователя, обычно расположенная в `/home/username`. Служит для хранения пользовательских файлов, конфигураций приложений (dotfiles) и рабочих данных. Права доступа обычно `700` или `750`.

### Стандартные права доступа (rwx)
Базовая модель прав в Linux, разделяющая доступ на три категории: Владелец (Owner), Группа (Group) и Остальные (Others). Для каждой категории задаются права на чтение (r, 4), запись (w, 2) и выполнение (x, 1).

### Umask (User File-creation Mode Mask)
Маска прав, которая определяет, какие права доступа будут *запрещены* по умолчанию при создании новых файлов и директорий. Вычитается из базовых прав (666 для файлов, 777 для директорий).

### SUID (Set User ID)
Специальный бит прав (числовое значение 4), который при установке на исполняемый файл заставляет процесс запускаться с правами владельца этого файла, а не пользователя, который его запустил.

### SGID (Set Group ID)
Специальный бит прав (числовое значение 2). При установке на исполняемый файл процесс запускается с правами группы владельца. При установке на директорию все новые файлы и поддиректории внутри неё автоматически наследуют группу этой директории.

### Sticky Bit (Липкий бит)
Специальный бит прав (числовое значение 1), применяемый к директориям. Он ограничивает право на удаление или переименование файлов внутри директории: это может сделать только владелец файла, владелец самой директории или пользователь root.

### chown / chgrp
Утилиты командной строки для изменения владельца (chown) и группы (chgrp), которым принадлежит файл или директория.

### chmod
Утилита для изменения стандартных прав доступа (rwx) и специальных битов (SUID, SGID, Sticky) у файлов и директорий.

### Неизменяемый атрибут (Immutable bit)
Специальный атрибут файловой системы (устанавливается через chattr +i), который запрещает любое изменение файла: удаление, переименование, запись или создание жестких ссылок, даже для пользователя root.
