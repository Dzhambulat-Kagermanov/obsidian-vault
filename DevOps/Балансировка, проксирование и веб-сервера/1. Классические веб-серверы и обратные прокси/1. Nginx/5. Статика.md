## Введение

Одна из главных причин популярности Nginx — его феноменальная скорость в отдаче статических файлов. В современной веб-архитектуре действует "золотое правило": **веб-сервер (Nginx) должен отдавать статику, а приложение (Node.js, Python, PHP) должно заниматься только динамической логикой**.

Попытка отдать статический файл через приложение (например, через Express.js или Django) тратит ценные ресурсы процесса приложения, память и циклы процессора на задачу, с которой Nginx справляется на порядки эффективнее благодаря системным вызовам ядра Linux.

## 1. Фундамент: `root` против `alias`

Это самая частая причина ошибок "404 Not Found" при настройке статики. Обе директивы указывают Nginx, где искать файлы, но делают это по-разному.

### Таблица различий

| Директива   | Как работает                                                   | Пример конфигурации                             | Запрос `/images/logo.png` превратится в путь                 |
| ----------- | -------------------------------------------------------------- | ----------------------------------------------- | ------------------------------------------------------------ |
| **`root`**  | Добавляет значение директивы **перед** URI запроса.            | `location /images/ { root /var/www; }`          | `/var/www` + `/images/logo.png` = `/var/www/images/logo.png` |
| **`alias`** | **Заменяет** совпавшую часть `location` на указанное значение. | `location /images/ { alias /var/www/static/; }` | `/var/www/static/` + `logo.png` = `/var/www/static/logo.png` |

- **`root`** — это как если бы вы сказали курьеру: "Добавь вот этот префикс к тому адресу, который я тебе дал".
- **`alias`** — это как если бы вы сказали курьеру: "Замени вот эту часть адреса на другую".



>[!WARNING] Критическое правило для `alias`
> Если вы используете `alias` внутри `location`, путь в `alias` **обязательно** должен заканчиваться косой чертой (`/`), если и `location` заканчивается косой чертой. Иначе Nginx склеит пути некорректно.

## 2. Стандартный паттерн: `try_files`

Директива `try_files` — это стандарт де-факто для обслуживания статических файлов с фоллбеком (резервным вариантом). Она проверяет существование файлов в указанном порядке и обслуживает первый найденный.

```nginx
location / {
    # 1. Ищем точное совпадение с URI ($uri)
    # 2. Ищем директорию с таким именем ($uri/)
    # 3. Если ничего нет, внутренне перенаправляем запрос на /index.html
    try_files $uri $uri/ /index.html;
}
```

**Почему это важно для SPA (React, Vue, Angular):** В одностраничных приложениях маршрутизация происходит на стороне клиента. Если пользователь обновит страницу по адресу `/dashboard/settings`, Nginx не найдет такой физический файл или папку. `try_files` перехватит это и отдаст `index.html`, позволив JavaScript-роутеру приложения отрисовать нужный экран.

## 3. Оптимизация производительности "под капотом"

Чтобы отдавать файлы максимально быстро, Nginx использует комбинацию директив, работающих в связке с ядром Linux.

```nginx
http {
    # 1. Включаем sendfile (zero-copy)
    sendfile on;
    
    # 2. Оптимизируем отправку пакетов (работает только вместе с sendfile)
    tcp_nopush on;
    
    # 3. Отключаем задержку отправки мелких пакетов (для keepalive)
    tcp_nodelay on;
    
    # 4. Кэшируем дескрипторы файлов (резко снижает нагрузку на диск при частых запросах)
    open_file_cache max=10000 inactive=20s;
    open_file_cache_valid 30s;
    open_file_cache_min_uses 2;
    open_file_cache_errors on;
}
```

1. **`sendfile on`**: Вместо того чтобы читать файл с диска в память Nginx (user-space), а затем из памяти Nginx в сетевой сокет, ядро Linux копирует данные напрямую из дискового кэша (page cache) в сокет. Это экономит 2 операции копирования памяти и переключения контекста.
2. **`tcp_nopush on`**: Говорит ядру: "Не отправляй HTTP-заголовки и начало файла отдельными мелкими пакетами. Подожди, пока наберется полный TCP-сегмент (около 1460 байт), и отправь всё разом". Это увеличивает пропускную способность.
3. **`open_file_cache`**: При запросе файла Nginx обычно делает системные вызовы `open()` и `stat()`. Эта директива сохраняет результаты этих вызовов в памяти на 20 секунд. Если файл запросят снова, Nginx возьмет данные из кэша, не обращаясь к диску.

## 4. Управление кэшированием в браузере (Client-Side Caching)

Чтобы снизить нагрузку на сервер, нужно заставить браузер клиента сохранять файлы у себя. Для этого используются HTTP-заголовки.

```nginx
location ~* \.(jpg|jpeg|png|gif|ico|css|js|woff2|svg)$ {
    # Устанавливаем срок действия кэша в 1 год
    expires 1y;
    
    # Добавляем заголовок Cache-Control для современных браузеров
    add_header Cache-Control "public, immutable";
    
    # Отключаем логирование успешных запросов к статике, чтобы не засорять логи
    access_log off;
}
```

> [!WARNING] Проблема устаревшего кэша
> Если вы установите `expires 1y`, а затем обновите файл `style.css` на сервере, клиенты будут использовать старую версию из кэша целый год. **Решение (Cache Busting)**: Системы сборки (Webpack, Vite) добавляют хэш к имени файла при каждом изменении (например, `style.a1b2c3.css`). В HTML ссылается на новый файл, браузер загружает его как новый, а старый со временем удаляется из кэша.

## 5. Безопасность при отдаче статики

Открытый доступ к файлам требует строгих ограничений, чтобы не раскрыть служебную информацию.

### Запрет доступа к скрытым файлам

```nginx
# Запрещаем доступ к любым файлам или директориям, начинающимся с точки (.git, .env, .htaccess)
location ~ /\. {
    deny all;
    access_log off;
    log_not_found off;
}
```

### Скрытие версии Nginx

```nginx
# В блоке http или server
server_tokens off;
```

_Это убирает версию Nginx из заголовка `Server` и страниц ошибок, усложняя работу злоумышленникам по поиску специфичных уязвимостей._

### Защита от Directory Traversal

Nginx по умолчанию защищает от атак вида `../../etc/passwd`, но при использовании `alias` с регулярными выражениями нужно быть осторожным. Всегда используйте `^~` или строгие регулярные выражения с `alias`, чтобы избежать обхода путей.

## 6. Практические сценарии для DevOps

### Сценарий 1: Идеальная конфигурация для SPA (React/Vue)

```nginx
server {
    listen 80;
    server_name myapp.com;
    root /var/www/myapp/dist; # Путь к собранным файлам
    index index.html;

    # 1. Отдаем статику с агрессивным кэшированием
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        access_log off;
    }

    # 2. Для всего остального пробуем найти файл, папку или отдаем index.html
    location / {
        try_files $uri $uri/ /index.html;
        
        # Заголовки безопасности для HTML
        add_header X-Content-Type-Options "nosniff";
        add_header X-Frame-Options "SAMEORIGIN";
    }
}
```

### Сценарий 2: Раздача тяжелых файлов (например, ISO-образов или архивов)

Для больших файлов важно отключить буферизацию проксирования (если они идут с бэкенда) или оптимизировать прямую отдачу.

```nginx
location /downloads/ {
    root /var/www/files;
    
    # Для очень больших файлов можно отключить sendfile, если используется aio,
    # но в 99% случаев sendfile on + tcp_nopush on работают лучше всего.
    sendfile on;
    tcp_nopush on;
    
    # Разрешаем докачку (Range requests)
    # Nginx поддерживает это по умолчанию, но важно не отключать это модулями
}
```

### Сценарий 3: Автоматизация через Ansible

```jinja2
# templates/static_site.conf.j2
server {
    listen 80;
    server_name {{ domain }};
    root {{ document_root }};

    location ~* \.({{ static_extensions | join('|') }})$ {
        expires {{ cache_expiry }};
        add_header Cache-Control "public";
        access_log off;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

## 7. Troubleshooting и типичные проблемы

|Проблема|Причина|Решение|
|---|---|---|
|**403 Forbidden** при запросе файла|1. У пользователя `www-data` нет прав на чтение файла.  <br>2. Нет права на выполнение (`+x`) у родительских директорий.  <br>3. Отсутствует индексный файл, а автоиндекс (`autoindex`) отключен.|Проверить права: `namei -om /путь/к/файлу`. Убедиться, что все директории в пути имеют `+x` для группы/остальных.|
|**404 Not Found**, хотя файл существует|Ошибка в логике `root` vs `alias`. Nginx ищет файл не там, где вы думаете.|Включить отладочный лог: `error_log /var/log/nginx/error.log debug;`. Посмотреть точный путь, который пытается открыть Nginx.|
|Браузер показывает старую версию CSS/JS|Агрессивное кэширование (`expires`) без использования cache busting (хэшей в именах файлов).|Настроить систему сборки на добавление хэшей к именам файлов. Временно отключить кэш в браузере для проверки.|
|Высокая нагрузка на CPU при отдаче статики|Отключен `sendfile` или `open_file_cache`, либо файлы слишком мелкие и генерируются динамически.|Включить `sendfile on;` и `open_file_cache`. Проверить, не проксируются ли статические файлы на бэкенд по ошибке.|
